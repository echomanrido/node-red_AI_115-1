主題一：MySQL / MariaDB 關聯式資料庫實作指南 (Step by Step)

開啟獨立實作手冊

MySQL 是世界上最流行的開源關聯式資料庫（RDBMS），廣泛應用於工廠 MES 系統的工單管理、人員權限配置與產品履歷追溯。以下為從無到有的標準架設與設定步驟：

1

安裝 MySQL 伺服器與設定監聽 IP

環境建置

在 Windows 或 Linux 工業電腦安裝 MySQL Community Server（預設通訊埠為 3306）。若要允許機台或 Node-RED 跨電腦連線，必須修改組態檔 my.ini (Windows) 或 mysqld.cnf (Linux)： 

# 預設為 bind-address = 127.0.0.1 (只允許本機)
# 修改為 0.0.0.0 允許局域網內所有工業機台連線
[mysqld]
port = 3306
bind-address = 0.0.0.0
2

設定 root 帳號允許外部遠端連線 (投影片 Slide 04-01 核心)

安全權限

剛安裝完 MySQL 時，root 預設只允許本機（localhost）登入。若從遠端 C# 程式或 Node-RED 連線會發生存取遭拒的錯誤。使用以下 SQL 指令進行遠端授權： 

-- 登入 MySQL 資料庫管理終端：
USE mysql;

-- 方案 A：直接修改 root 允許任意主機連線 (%)
UPDATE user SET host = '%' WHERE user = 'root';
FLUSH PRIVILEGES;

-- 方案 B (工控現場標準做法)：建立專用操作員帳號
CREATE USER 'factory_operator'@'%' IDENTIFIED BY 'FactoryPass123!';
GRANT ALL PRIVILEGES ON FactoryDB.* TO 'factory_operator'@'%';
FLUSH PRIVILEGES;
3

建立工廠生產資料庫與結構化資料表

DDL 實作

設計符合工業生產履歷追溯的結構化資料表，包含自動累加主鍵、機台編號、工單號、良品數、不良品數與記錄時間： 

CREATE DATABASE IF NOT EXISTS FactoryDB CHARACTER SET utf8mb4;
USE FactoryDB;

CREATE TABLE production_records (
    id INT AUTO_INCREMENT PRIMARY KEY,
    work_order VARCHAR(50) NOT NULL COMMENT '工單編號',
    machine_id VARCHAR(30) NOT NULL COMMENT '機台代號 (如 CNC_01, FX3U_02)',
    feed_qty INT DEFAULT 0 COMMENT '進料數量',
    discharge_qty INT DEFAULT 0 COMMENT '出料數量',
    defect_qty INT DEFAULT 0 COMMENT '不良數量',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP COMMENT '紀錄時間',
    INDEX idx_machine (machine_id),
    INDEX idx_created (created_at)
) ENGINE=InnoDB;

主題二：Microsoft SQL Server 與 C# 視窗程式整合實作 (Step by Step)

開啟獨立實作手冊

SQL Server 是微軟生態系中最穩定的企業級資料庫。搭配 C# WinForms / WPF 視窗與 DataGridView，可打造工業機台控制台上最流暢的即時查詢與資料錄入系統。

1

SSMS 新增資料表與規劃欄位型別

SSMS 操作

開啟 SQL Server Management Studio (SSMS)，連線至本機伺服器 localhost：

  • 右鍵點選「資料庫」➔「新增資料庫」➔ 命名為 FactoryDB。
  • 展開 FactoryDB ➔ 右鍵「資料表」➔「新增」➔「資料表」。
  • 欄位規劃：LogID (int, 主鍵, 識別規格=是)、MachineName (nvarchar(50))、FeedCount (int)、DischargeCount (int)、RecordTime (datetime2, 預設 GETDATE())。
  • 儲存資料表並命名為 MachineLogs。
2

新增使用者並指定授予特定資料庫權限

安全與授權

在企業產線中，絕不能直接將 sa 最高管理員密碼寫死在 C# 程式碼中：

  1. 在 SSMS 展開伺服器層級「安全性」➔ 右鍵「登入身分」➔「新增登入身分」。
  2. 選擇「SQL Server 驗證」，輸入登入名稱（如 app_user）與密碼。
  3. 點選左側「使用者對應」➔ 勾選 FactoryDB。
  4. 在下方資料庫角色成員資格中，勾選 db_datareader (讀取權限) 與 db_datawriter (寫入權限) 即可。
3

C# 撰寫查詢代碼並繫結至 DataGridView

C# ADO.NET

在 Visual Studio 建立 Windows Forms 專案，拖曳放置一個 DataGridView（名稱為 dgvLogs）與「查詢」按鈕： 

using System;
using System.Data;
using System.Data.SqlClient;
using System.Windows.Forms;

public void LoadMachineLogs()
{
    string connStr = "Server=localhost;Database=FactoryDB;User Id=app_user;Password=YourPass123;";
    string sql = "SELECT TOP 100 LogID, MachineName, FeedCount, DischargeCount, RecordTime FROM MachineLogs ORDER BY RecordTime DESC";

    try
    {
        using (SqlConnection conn = new SqlConnection(connStr))
        {
            conn.Open();
            using (SqlDataAdapter adapter = new SqlDataAdapter(sql, conn))
            {
                DataTable dt = new DataTable();
                adapter.Fill(dt);
                dgvLogs.DataSource = dt; // 一行代碼完成表格數據綁定
            }
        }
    }
    catch (Exception ex)
    {
        MessageBox.Show("查詢資料庫失敗: " + ex.Message, "錯誤", MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
}

C# 參數化安全寫入資料 (防止 SQL Injection)

C# 寫入

工控介面上由作業員輸入或 PLC 觸發寫入時，務必採用 SqlCommand.Parameters 傳參： 

public bool InsertLog(string machineName, int feed, int discharge)
{
    string connStr = "Server=localhost;Database=FactoryDB;User Id=app_user;Password=YourPass123;";
    string sql = @"INSERT INTO MachineLogs (MachineName, FeedCount, DischargeCount, RecordTime) 
                   VALUES (@machine, @feed, @discharge, GETDATE())";

    using (SqlConnection conn = new SqlConnection(connStr))
    {
        using (SqlCommand cmd = new SqlCommand(sql, conn))
        {
            cmd.Parameters.AddWithValue("@machine", machineName);
            cmd.Parameters.AddWithValue("@feed", feed);
            cmd.Parameters.AddWithValue("@discharge", discharge);
            conn.Open();
            int rows = cmd.ExecuteNonQuery();
            return rows > 0;
        }
    }
}

Grafana 儀表板整合與「時間多 8 小時」除錯攻略

痛點排解

在 Grafana（http://localhost:3000，預設帳密 admin/admin）中新增 Microsoft SQL Server 資料來源。製作時序曲線圖時，開發者常遇到「數據曲線跑到 8 小時後」的現象：

問題核心原因： Grafana 預期資料庫回傳的 time 欄位是 UTC 零時區。若 SQL Server 欄位儲存的是台灣本地時間 (GMT+8)，Grafana 在前端渲染時會依照瀏覽器時區再次 +8 小時，導致時間總共多了 8 小時！

雙重最佳解法：

-- 解法 1 (SQL 查詢扣除 8 小時轉為標準 UTC)：
SELECT 
  DATEADD(hour, -8, RecordTime) as time,
  FeedCount as value,
  MachineName as metric
FROM MachineLogs
WHERE $__timeFilter(DATEADD(hour, -8, RecordTime))
ORDER BY time ASC;

-- 解法 2 (Grafana Dashboard 設定)：
-- 進入 Dashboard Settings ➔ Time Options ➔ 將 Timezone 從 "Default (browser)" 改為 "UTC"。

主題三：InfluxDB 2.x 時序資料庫架構與實作指南 (Step by Step)

開啟獨立實作手冊

InfluxDB 專為處理帶有時間戳記的海量高頻數據而生（如振動分析、每秒萬次採樣）。具備 TSM 樹、列式儲存 與 Gorilla 差值壓縮，是邊緣運算與工業物聯網（IIoT）的不二之選。

1

Docker 一鍵啟動 InfluxDB 2.x 伺服器

Docker 容器

使用官方 Docker 映像檔，並預先配置組織（Org）、儲存桶（Bucket）與認證 Token： 

docker run -d -p 8086:8086 --name influxdb \
  -e DOCKER_INFLUXDB_INIT_MODE=setup \
  -e DOCKER_INFLUXDB_INIT_USERNAME=my-admin-user \
  -e DOCKER_INFLUXDB_INIT_PASSWORD=my-secret-password123 \
  -e DOCKER_INFLUXDB_INIT_ORG=my-org \
  -e DOCKER_INFLUXDB_INIT_BUCKET=production_data \
  -e DOCKER_INFLUXDB_INIT_ADMIN_TOKEN=my-super-secret-auth-token-123 \
  influxdb:2.7.5

啟動後開啟瀏覽器訪問 http://localhost:8086，即可使用上述設定之帳號密碼登入管理後台。

2

精通 Line Protocol 格式規範與整數 'i' 規則

協定語法

Line Protocol 是純文字單行協定。空格與逗號有著嚴格定義：

<measurement>,<tag_key>=<tag_value> <field_key>=<field_value> <timestamp>
  • Measurement 與 Tag 之間用逗號分隔：例如 production_stats,machine_name=PLC_01。
  • Tag 與 Field 之間必須用「空格」分隔。
  • 整數型別必須加 i：例如 feed=10i。若不加 i（如 feed=10），InfluxDB 會自動解析為 Float 浮點數，後續無法在同一 Series 內寫入整數！
  • Timestamp：可帶 19 位納秒戳記，亦可省略由伺服器自動補充。

深入底層架構：TSM 引擎、WAL 預寫日誌與 Gorilla 演算法

架構原理解析

傳統關聯式資料庫每秒寫入千筆硬碟就滿載，而 InfluxDB 單機每秒可扛 10~50 萬筆寫入，其背後的儲存心臟關鍵設計：

WAL + MemTable 高速寫入

資料先以 Append-only 追加寫入 WAL 檔案防斷電，同時放入記憶體 MemTable。當 MemTable 達時間或大小閾值後，Flush 刷盤為唯讀的 .tsm 列式儲存檔，後台背景再執行 Compaction 壓縮合併。

Gorilla 差值時間壓縮

由於時間戳記通常是固定週期（如每 100ms 一次），Gorilla 演算法透過計算前後時間的差值（Delta）以及差值的差值（Delta-of-Delta），將原本 64 位元的納秒整數壓縮至僅需 1~2 個 bit，壓縮率達 90% 以上！

4

Flux 查詢實戰：時序過濾與 Pivot 橫向展開

Flux 查詢

InfluxDB 2.x 使用類似管線傳遞（Pipeline |>）的 Flux 語言。以下範例查詢近 90 天生產數據，並利用 pivot() 將縱向 Field 展開為平整的機台日報表： 

from(bucket: "production_data")
  |> range(start: -90d)
  |> filter(fn: (r) => r._measurement == "production_stats")
  |> pivot(rowKey: ["_time", "machine_name"], columnKey: ["_field"], valueColumn: "_value")
  |> sort(columns: ["_time"], desc: true)
  |> limit(n: 200)

JavaScript SDK 即時監聽 (onSnapshot) 實作代碼

即時串接

利用 Firestore 內建的 WebSocket 即時推送功能，機台數據一旦在工廠端變更，全球主管的手機戰情看板完全無需重新整理 (No Refresh)，毫秒級自動更新： 

import { initializeApp } from "https://www.gstatic.com/firebasejs/10.7.1/firebase-app.js";
import { getFirestore, doc, onSnapshot } from "https://www.gstatic.com/firebasejs/10.7.1/firebase-firestore.js";

const firebaseConfig = {
  apiKey: "YOUR_API_KEY",
  projectId: "wugu-factory-ai"
};

const app = initializeApp(firebaseConfig);
const db = getFirestore(app);

// 即時監聽五股廠 FX3U 機台狀態文件
const docRef = doc(db, "factories", "plant_wugu_01", "telemetry", "fx3u_line_a");
onSnapshot(docRef, (docSnap) => {
  if (docSnap.exists()) {
    const data = docSnap.data();
    console.log("機台即時狀態更新:", data);
    document.getElementById("feedDisplay").innerText = data.feed_qty;
    document.getElementById("statusDot").className = data.is_running ? "green" : "red";
  }
});
5

設定 Firestore 安全規則 (Security Rules)

資安規範

在生產環境中，切勿使用全開權限。透過規則驗證使用者身份與角色： 

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // 機台遙測數據：所有登入工程師可讀，僅授權邊緣網關可寫入
    match /factories/{factoryId}/telemetry/{machineId} {
      allow read: if request.auth != null;
      allow write: if request.auth.token.role == "gateway" 
                   && request.resource.data.feed_qty is int;
    }
  }
}
