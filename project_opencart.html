主題一：XAMPP 與 OpenCart 基礎環境建置 (循序漸進 Step by Step)

本主題從零搭建 LAMP/WAMP 架構，排解 Windows 系統 80 Port 占用問題，設定 PHP 運作環境，並順利啟動 OpenCart 4.x 繁體中文購物商城。

1

下載並安裝 XAMPP 整合套件

前往 Apache Friends 官網下載適用 Windows 之 XAMPP 套件，安裝至 C:\xampp。套件內含 Apache (Web伺服器)、MariaDB (MySQL資料庫)、PHP (解析引擎) 與 phpMyAdmin。

2

解決常見故障：80 Port 被 System (PID 4) 占用鎖死

若 Apache 啟動失敗出現紅字，通常是 Windows 內建之 HTTP.SYS 占用了 80 Port。請以系統管理員身分開啟 CMD 執行以下指令：

Command Prompt (CMD - 系統管理員) 
net stop http
sc config http start= disabled
執行後在 XAMPP 點擊 Apache Start，即可看到綠燈順利亮起！
3

解壓縮 OpenCart 並調整 php.ini 擴充設定

將 opencart-4.x.zip 中的 upload 資料夾解壓縮至 C:\xampp\htdocs\opencart。接著點選 XAMPP Apache 旁的 Config -> PHP (php.ini)，搜尋並拿掉下列模組行首的分號 ;： 

extension=curl
extension=gd
extension=mbstring
extension=openssl
extension=zip
4

關鍵更名：config-dist.php 改為 config.php

OpenCart 規定安裝前必須手動將樣板檔重新命名，否則安裝精靈會報錯無法寫入：

  • 將 C:\xampp\htdocs\opencart\config-dist.php 重新命名為 config.php
  • 將 C:\xampp\htdocs\opencart\admin\config-dist.php 重新命名為 config.php
5

phpMyAdmin 建立資料庫與安裝精靈設定

開啟 http://localhost/phpmyadmin/，建立名為 db_opencart (編碼 utf8mb4_general_ci) 的資料庫。接著瀏覽器進入 http://localhost/opencart/install/index.php，資料庫使用者填 root、密碼留空，並設定後台管理者帳號密碼完成安裝。

6

安裝繁中語系包與新增「工件」商品分類

下載 zh-TW-4.zip 解壓縮置入語言目錄，至後台 System -> Localisation -> Languages 新增繁體中文並設為商店預設語系。最後至 Catalog -> Categories 新增分類名稱「工件 (workpiece)」，勾選「在頂部選單顯示 (Top)」，前台首頁導覽列便會立即呈現工件專區！

主題二：網路商城設定與工件管理 (規格屬性、下單實測與資料表剖析)

本主題聚焦於工業工件之標準化上架流程，實測客戶端購物車結帳機制，並深入剖析 MariaDB 中支撐智慧製造運轉的關鍵資料表結構。

1

自訂工業工件屬性 (Attributes) 與規格選項 (Options)

在後台 Catalog -> Attributes 建立「加工規格」群組，新增「工件材質 (Material)」與「加工公差 (Tolerance)」屬性；在 Options 新增「表面處理」選項 (陽極氧化、染黑、拋光)，模擬現場製造多樣化客製需求。

2

正式上架商品：精密圓形工件 (WP-RND-001)

至 Catalog -> Products 點擊新增。填寫品名「精密圓形工件」、型號「WP-RND-001」、單價「150 元」、設定庫存「100 件」，並關聯至「工件」分類與上傳 CAD 渲染圖，完成上架。

3

前台下單流程實測 (產生測試訂單)

開啟前台商城 http://localhost/opencart/，進入「工件」專區選購 5 件「精密圓形工件」加入購物車。點擊結帳並註冊測試帳號，選擇貨到付款完成送出，系統立即產生真實訂單 (如 Order #10)。

主題三：SQL 語法簡介與電商資料庫精準查詢 (全國技能競賽重點)

SQL 是控制與擷取工業資料庫的關鍵語言。本主題涵蓋基礎查詢、資料更新、外部連接，以及第 53 屆全國技能競賽「工業 4.0」專用的多層巢狀子查詢 (Subquery)。

1

基礎篩選查詢：篩選未完成之待產訂單

排除已完工 (status=5) 與已取消 (status=7) 的訂單，精準取出待排程的訂單編號：

SQL Query 
SELECT `order_id` FROM `oc_order` WHERE `order_status_id` != '5' AND `order_status_id` != '7';
2

多表連接 LEFT JOIN：查詢訂單關聯之工件品名與加工數量

將訂單主表 oc_order 與明細表 oc_order_product 依據 order_id 關聯，獲取工件品名與生產數量：

SQL Query (LEFT JOIN) 
SELECT 
    oc_order.order_id, 
    oc_order_product.name AS workpiece_name, 
    oc_order_product.quantity AS target_qty
FROM oc_order
LEFT JOIN oc_order_product ON oc_order.order_id = oc_order_product.order_id
WHERE oc_order.order_id = 10;
3

狀態更新 UPDATE 與歷程寫入 INSERT INTO (加急派工)

當產線決定加急插單時，同步變更訂單狀態碼為 99 並於歷史表留下紀錄。注意：UPDATE 絕對不可遺漏 WHERE 條件！

SQL DML (UPDATE + INSERT) 
-- 1. 更新訂單狀態為加急 (order_status_id = 99)
UPDATE oc_order SET order_status_id = 99 WHERE order_id = 10;

-- 2. 插入歷史紀錄
INSERT INTO oc_order_history (order_id, order_status_id, notify, comment, date_added) 
VALUES (10, 99, 1, '現場作業員透過 Node-RED MES 啟動加急作業', NOW());
4

國手競賽級：兩階段巢狀子查詢 (待生產工件總量統計)

若一筆訂單有多項工件，直接簡單 SUM 會造成分組混亂。標準做法是先由內層依 order_id 分組計算各訂單工件總數，再由外層加總出全廠待生產工件總數：

SQL Subquery (待生產工件總量) 
SELECT SUM(total_quantity) AS grand_total_quantity FROM (
    SELECT 
        oc_order.order_id, 
        oc_order.order_status_id, 
        SUM(oc_order_product.quantity) AS total_quantity 
    FROM oc_order 
    LEFT JOIN oc_order_product ON oc_order.order_id = oc_order_product.order_id 
    WHERE oc_order.order_status_id < '5' 
    GROUP BY oc_order.order_id, oc_order.order_status_id
) AS subquery;
5

國手競賽級：兩階段巢狀子查詢 (已完工工件總量統計)

將篩選條件改為 order_status_id = '5' (已完成 Complete)，即可高速統計出全廠已完工合格入庫的工件總數：

SQL Subquery (已完工工件總量) 
SELECT SUM(total_quantity) AS grand_total_quantity FROM (
    SELECT 
        oc_order.order_id, 
        oc_order.order_status_id, 
        SUM(oc_order_product.quantity) AS total_quantity 
    FROM oc_order 
    LEFT JOIN oc_order_product ON oc_order.order_id = oc_order_product.order_id 
    WHERE oc_order.order_status_id = '5' 
    GROUP BY oc_order.order_id, oc_order.order_status_id
) AS subquery;

主題四：Node-RED 串接電商資料庫與智慧製造實戰 (MES 邊緣系統)

本主題使用 Node-RED 與 node-red-node-mysql、node-red-dashboard 打造全自動化工廠 MES 調度中心，涵蓋動態下拉選單、加急更新、LED 動態加工狀態機與產能良率 KPI 儀表。

1

單元一：動態訂單下拉選單 (msg.options 轉換機制)

透過 MySQL 節點定時查詢未完工工單，利用 Function 節點將資料庫 Array 封裝成 Dashboard 要求的 msg.options 格式，讓作業員能隨時選擇當前待切削之工單： 

let options = [];
if (Array.isArray(msg.payload) && msg.payload.length > 0) {
    msg.payload.forEach(row => {
        options.push({ label: "待產工單 #" + row.order_id, value: row.order_id });
    });
    msg.options = options;
    msg.payload = options[0].value;
    flow.set("selected_order_id", msg.payload);
}
return msg;
2

單元二：一鍵訂單加急機制 (Emergency Push)

點擊 Dashboard 的「🚨 訂單加急處理」紅色按鈕，Node-RED 立即組裝多重 SQL 指令將 order_status_id 提升為加急狀態，同時寫入 oc_order_history 並彈出 Toast 提示視窗，實現敏捷調度。

3

單元三：虛擬機台切削加工模擬與動態 LED 燈號

在 ui_template 節點中使用 HTML/CSS 打造自適應圓形狀態燈號，模擬機台加工循環： 

<div style="text-align: center; padding: 12px; background: rgba(0,0,0,0.2); border-radius: 8px;">
    <div style="border: 2px solid #ffffff; border-radius: 50%; width: 50px; height: 50px; margin: 0 auto; 
                box-shadow: 0 0 16px {{msg.payload || '#10b981'}}; background-color: {{msg.payload || '#10b981'}};">
    </div>
    <div style="margin-top: 10px; font-weight: bold; color: #f8fafc;">
        <span ng-bind="msg.status_text || '機台待機中 (Standby)'"></span>
    </div>
</div>
  • 待機狀態：綠燈 (#10b981)，顯示「機台待機中」。
  • 切削中狀態：點擊啟動，切換為橙黃燈 (#f59e0b)，進入 4 秒延遲模擬切削。
  • 完工回寫：延遲結束，藍燈閃爍提示完工，自動執行 SQL 將 order_status_id 更新為 5 (已完成)！
4

單元四：產能指標 KPI 看板與即時良率計算 (Yield Rate)

定時觸發主題三的兩階段巢狀子查詢，並整合現場不良品數量，在 Function 節點計算出即時全廠良率百分比： 

let completeCount = flow.get("kpi_complete") || 0;
let defectCount = flow.get("kpi_defects") || 2; // 抽檢不良品
let totalProduced = completeCount + defectCount;
let yieldRate = totalProduced > 0 ? ((completeCount / totalProduced) * 100).toFixed(1) : 100.0;
msg.payload = parseFloat(yieldRate);
return msg;

數據自動導向 Dashboard 的 Gauge 圓形儀表板，分別呈現「待生產工件數 (藍/橙/紅)」、「已完工工件數 (綠)」與「產線即時良率 (0~100%)」，打造直覺專業的戰情室儀表板！

5
