小撇步：獨立工作區概念
Workspace（工作區） 是隔離不同專案、部門或知識庫的容器。每個工作區可以獨立配置專屬的 LLM 模型、Prompt 提示詞與專屬文件檔案庫。

智慧代理人 (Agent) 與 SearXNG 免費聯網

RAG vs 智慧代理人

傳統 RAG 僅是被動檢索知識庫並產生文字；而 智慧代理人 (Agent) 具備工具調用 (Tool Calling) 與多步驟思考能力。

如何喚醒：
在工作區對話框中輸入 @agent 後接續指令，即可喚醒代理人執行技能。
  • 檢視並摘要長篇文件
  • 爬取網頁即時內容
  • 即時網路搜尋與整合回覆

雙欄式文件管理

文字分割與切塊 (Chunking) 的權衡

文字區塊大小 (Chunk Size，投影片預設: 1000 字元)

• 設太小 (200~300)：命中精確，但語意容易被腰斬，模型看不到上下文。
• 設太大 (2000~4000)：保留完整章節，但向量主題被稀釋，不易精準命中微小細節，並占用 LLM 窗口。

文字切塊重疊 (Chunk Overlap，投影片預設: 20 字元)

避免「邊界斷裂 (Boundary Issue)」。若一句關鍵停機 SOP 剛好橫跨第 1 塊末端與第 2 塊開頭，重疊能確保這句話完整出現在至少一個區塊中。

💡 實務工程優化建議： 業界常見的最佳實務為 10% ~ 20% 重疊率。若 Chunk Size 設為 1000，建議將 Overlap 調整至 100 ~ 200，檢索召回穩定度大幅提升！

投影片案例分析：PLC 異常找誰？ (投影片 P.18)

經驗法則： 較小參數語言模型（如超輕量小模型）理解力與長度有限，常無法順利從 RAG 檢索出正確邏輯；而適中或較大語言模型（如 4B / 8B 以上或雲端模型）則幾乎不會產生幻覺。

REST API 整合與 Node-RED 自動化串接

AnythingLLM Swagger API 文檔與金鑰授權

內建完整 OpenAPI 規範介面，本地預設監聽在 3001 連接埠。

http://localhost:3001/api/docs/#/
UI 截圖參考：投影片 P.21 Swagger 首頁與 P.23 BearerAuth 授權窗
步驟 1. 生成 API Key (投影片 P.24)

前往 工具 > 開發者 API，點擊右上角「產生新的 API 金鑰」並複製。

步驟 2. Swagger 授權 (投影片 P.23)

在 Swagger 頁面右上角點擊 Authorize 🔒，輸入 Bearer Token 驗證。

步驟 3. 取得 Workspace Slug (投影片 P.25)

呼叫 GET /v1/workspaces 找到對應工作區的專屬 slug（如 ai_test）。

Method Endpoint (端點) 功能說明 重要參數 (Body / Path)
GET /v1/workspaces 取得當前所有工作區清單與設定 無
POST /v1/workspace/{slug}/chat 向指定工作區傳送提示並執行推理對話 { "message": "...", "mode": "chat" }
模式："mode": "chat" (推薦)

結合大語言模型的通用常識與知識庫向量切塊，支援滾動式歷史對話紀錄 (Rolling Chat History)，具備上下文連續問答能力。

模式："mode": "query" (純檢索)

純檢索模式：僅當向量資料庫中搜尋到高度相符的段落時才會調用模型，且不記錄任何對話歷史。適合單次精準問答或嚴格查表。

cURL 指令與 Node-RED 核心對應表 (投影片 P.28)

在 IoT、PLC 與工業機電整合中，常使用 Node-RED 透過 HTTP Request 節點調用 AnythingLLM。對話與推理紀錄也會同步反映在 AnythingLLM 介面中！

cURL 參數 / 選項 代表作用 Node-RED 對應設定方式
URL (位置參數) 請求伺服器位址 在 http request 節點配置中的 URL 欄位，或在 upstream 節點設定 msg.url
-X <METHOD> 指定 HTTP 方法 (GET/POST) 節點配置中的 Method 下拉選單，或設定 msg.method
-H <Header> 設定請求標頭 (認證/格式) 節點內 Headers 欄位，或由 Function 節點輸出 msg.headers
-d <Data> / --data 傳送請求內容 (JSON Body) 上游節點（如 Inject / Function）中包裝為物件傳入 msg.payload
輸出結果 伺服器回應與解答 JSON 由 http request 節點直接輸出於 msg.payload

                 地端 RAG 實戰排坑指南 (Best Practices)
            

            
            

                

                    
Q: 為什麼改了切塊設定沒反應？

                    

                        「文字分割與切塊」只會對後續新上傳的文件生效。已經解析並存入 LanceDB 向量庫的舊文件，必須點擊重新嵌入（Re-embed）或重新上傳檔案。
                    

                

                

                    
Q: 中文知識庫找不到資料？

                    

                        預設嵌入模型 all-MiniLM-L6-v2 專注於英文（僅23MB）。若文件為繁體中文，建議切換向量嵌入器為多語言支援模型（如 Ollama 中的 bge-m3 或 nomic-embed-text）。
                    

                

                

                    
Q: Node-RED 收到 403 錯誤？

                    

                        請檢查 Headers 中的 Authorization: Bearer <TOKEN> 是否完整填寫，且金鑰是否於 AnythingLLM 的「開發者 API」介面中處於啟用狀態。
