地端 LLM 實務教學：從模型部署到工控 RAG 閉環 Step-by-Step

1

Ollama 地端大模型部署與 Page Assist 瀏覽器外掛配置

Ollama CLI 實戰

1.1 下載與安裝 Ollama

至官方網站 ollama.com 下載 Windows 安裝檔，安裝後 Ollama 服務將常駐於系統列，並自動監聽本地 http://localhost:11434。

# 檢查 Ollama 版本與系統服務狀態 ollama --version # 拉取並運行 3B 級別超輕量多模態模型 (適合一般商務筆電或無獨顯環境) ollama run llama3.2-vision # 拉取並運行 Google Gemma 2 (9B / 27B) ollama run gemma2:9b # 拉取專用向量嵌入模型 (用於 RAG 切分比對) ollama pull embeddinggemma ollama pull nomic-embed-text

1.2 配置 Page Assist 瀏覽器 Web UI 與 Web Search 聯網搜尋

  • 安裝 Chrome 線上應用程式商店外掛：Page Assist - A Web UI for Local AI Models。
  • 開啟外掛選項 (Options)，確認 Ollama URL 指向 http://localhost:11434，即可看到本機所有拉取的模型。
  • 開啟 Web Search 功能：在地端模型回答時，可設定先以 SearXNG 實例或 Google API 爬取最新即時新聞或零件技術手冊，彌補訓練數據時間差，再交由地端模型總結輸出。
記憶體調優秘訣 (Context Length)：
預設 Ollama 上下文長度為 2048 tokens。若需處理整份機電說明書，可在 Modelfile 中寫入 PARAMETER num_ctx 8192 或 16384，善用顯卡 VRAM 避免上下文截斷！
2

AnythingLLM 企業知識庫 (RAG) 構建、向量檢索與 @agent 代理人

RAG 檢索增強生成

2.1 建立專屬工作區 (Workspace) 與資料庫選型

安裝 AnythingLLM 後，建立名為 factory-maintenance 的工作區。在設定中指定：

  • LLM Provider (語言模型提供者)：選擇本地 Ollama，模型選定 llama3.2 或 gemma2:9b。
  • Embedding Provider (向量模型)：選擇本地 Ollama (nomic-embed-text) 或內建引擎。
  • Vector Database (向量資料庫)：選用內建的高效 LanceDB（零配置、儲存於本機檔案、毫秒級比對），或切換至外部 ChromaDB。

2.2 文件上傳與向量切分 (Pin to Workspace)

將工廠現場的 機台故障常見處理流程.txt、三菱PLC_FX3U通信手冊.pdf 上傳至 AnythingLLM。系統會自動進行文字萃取、Chunk 切分與向量化，點擊「Pin to Workspace」即可將知識注入此工作區。

2.3 @agent 智慧代理人與外部技能調用

在對話框輸入 @agent，即可切換為 Agent 模式。AnythingLLM 能根據問題自主規劃步驟，調用網頁搜尋、計算機技能，甚至自動分析整份 PDF 文件，並給出精確的參考頁碼與章節引用，徹底消除大模型的胡言亂語（幻覺 Hallucination）！

3

LM Studio 圖形化模型管理與 OpenAI 相容 Local Server 架設

Local API Server

3.1 GGUF 量化模型下載與 GPU 層數卸載

LM Studio 提供直觀的模型搜尋介面，直接搜尋 Qwen2.5-Coder-7B、Meta-Llama-3-8B-Instruct。選擇 Q4_K_M（推薦性價比最高）或 Q8_0（高精度）下載。在右側側邊欄將 GPU Offload (GPU 層數卸載) 設為最大，讓幾十層的神經網路全數進駐顯卡顯存，推論速度提升 5~10 倍！

3.2 啟動本機 API 伺服器 (Port 1234)

點擊左側「Local Server」分頁，點選頂部「Start Server」。服務將在 http://localhost:1234 運行，提供標準端點：

# 檢驗本機當前載入之模型清單 curl http://localhost:1234/v1/models # 測試標準 OpenAI Chat Completion 格式 curl http://localhost:1234/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{ "model": "qwen2.5-coder-7b-instruct", "messages": [ {"role": "system", "content": "你是一位工業機電與 PLC 顧問。"}, {"role": "user", "content": "三菱 FX3U 如何設定 RS232 通信格式？"} ], "temperature": 0.7 }'
4

工控閉環整合：Node-RED & C# 串接地端 LLM 進行異常即時診斷

IoT + LLM 閉環

4.1 Node-RED HTTP Request 節點調用實務

當 Node-RED 透過 Modbus 或 PLC RS232 讀取到現場馬達溫度超過 75°C、或連續卡料時，立即觸發 Function 節點組織 Prompt，並以 http request 節點（方法：POST）拋送至本機 Ollama http://localhost:11434/api/generate：

// Node-RED Function 節點程式碼範例 msg.headers = { 'Content-Type': 'application/json' }; msg.payload = { model: "gemma2:9b", prompt: `[工廠警報系統]\n機台ID: M-01\n異常狀態: 主軸馬達溫度達到 78°C (警戒值 70°C)\n請根據機台常見故障處理流程，用繁體中文給出 3 點即時排查處置建議。`, stream: false }; return msg;

4.2 診斷結果反饋控制迴路

Node-RED 解析回傳的 JSON msg.payload.response 後：

  1. 將排查文字透過 LINE Bot 專題 拋送給機電維護值班工程師。
  2. 同時觸發寫入 PLC 暫存器（如 D200），命令變頻器降頻 20% 進行緊急保護降溫，達成無人化邊緣 AI 閉環保護！
