機器學習核心：模型複雜度與預測誤差曲線

在進入 Teachable Machine 實作之前，必須先理解「訓練集 (Training Set)」與「測試集/驗證集 (Test Set)」在不同模型複雜度下的行為差異，這是後續分析訓練成敗的理論核心。

模型複雜度與誤差變化圖 (參考馬維銘教授講義模型) 最佳平衡點：乙區

甲區：配適不足 (Underfitting)

模型過於單純，特徵提取能力太差。特徵是訓練集與測試集誤差皆偏高，無論丟什麼圖片都無法有效區分。

乙區：理想平衡 (Best Generalization)

測試集誤差降至最低谷，模型學會了真實世界的共用規律（泛化能力強），而非單純死記硬背。

戊區：過度配適 (Overfitting)

模型死記訓練集背景雜訊，訓練集誤差趨近 0，但遇到未見過的測試集誤差大幅回升，無法於實務上使用。

Epochs (訓練週期)

比喻：學生整本課本讀完幾次

所有訓練圖片通過神經網路來回傳遞（一次前向與一次反向傳播）的總遍數。
• 設太小： 欠擬合，還沒學好。
• 設太大： 過度擬合，死記細節。

預設: 16

Batch Size (批次大小)

比喻：一次看幾頁書才寫一次筆記

單次迭代中模型同時計算的一組影像數量。
• 較大批次： 訓練平穩快速，但吃更多記憶體。
• 較小批次： 隨機性強，助於跳脫局部低谷。

預設: 0.001

Learning Rate (學習率)

比喻：每次訂正錯誤的跨步幅度

梯度下降更新內部權重時的步長幅度。
• 步伐太大： 容易跳過最佳解，震盪發散。
• 步伐太小： 收斂極其緩慢，時間成本高。

3. Google Colab 執行 Keras 模型 (.h5) 與 Keras 3 版本相容修復

TensorFlow / Keras 3.x
常見報錯原因： Teachable Machine 匯出的 keras_model.h5 採用舊版 Keras 2 格式，直接在新版 Google Colab (Python 3.12 / Keras 3) 執行 load_model() 會拋出 ValueError: Unrecognized keyword arguments passed to DepthwiseConv2D: {'groups': 1}。透過下方自定義類別即可完美解決：
Python 3.12 + Keras 3 CustomDepthwiseConv2D 完整修復代碼 Colab Verified 
import tensorflow as tf
from keras.models import load_model
from PIL import Image, ImageOps
import numpy as np

np.set_printoptions(suppress=True)

# 1. 定義自訂 DepthwiseConv2D 類別，自動過濾新版 Keras 3 不相容的 'groups' 參數
class CustomDepthwiseConv2D(tf.keras.layers.DepthwiseConv2D):
    def __init__(self, **kwargs):
        if 'groups' in kwargs:
            del kwargs['groups']
        super().__init__(**kwargs)

# 2. 透過 custom_object_scope 載入模型與標籤檔
with tf.keras.utils.custom_object_scope({'DepthwiseConv2D': CustomDepthwiseConv2D}):
    model = load_model("/content/teachableMachine/keras_model.h5", compile=False)

class_names = open("/content/teachableMachine/labels.txt", "r").readlines()

# 3. 影像預處理 (縮放裁切為 224x224 並正規化至 [-1, 1])
data = np.ndarray(shape=(1, 224, 224, 3), dtype=np.float32)
image = Image.open("/content/jpg/Black.jpg").convert("RGB")
image = ImageOps.fit(image, (224, 224), Image.Resampling.LANCZOS)
normalized_image_array = (np.asarray(image).astype(np.float32) / 127.5) - 1
data[0] = normalized_image_array

# 4. 執行模型推論並輸出結果
prediction = model.predict(data)
index = np.argmax(prediction)
print("Class:", class_names[index][2:].strip())
print("Confidence Score:", prediction[0][index])

底層核心技術深度剖析與架構對比：Teachable Machine vs. YOLO

在視覺與多模態 AI 專案選型時，最常面臨「影像分類 / 時序識別」與「即時物件偵測」的抉擇。以下完整拆解 Google Teachable Machine（CNN + MobileNet + 遷移學習微調） 與 YOLO（單階段物件偵測 + Anchor-Free） 背後的神經網路核心技術。

G
影像分類 · 聲音時序 · 姿態骨架

1. Google Teachable Machine 核心技術深度解析

Engine: TensorFlow.js + WebGL GPU

Teachable Machine 並非從零開始訓練龐大的神經網路，而是巧妙結合「預訓練骨幹網路 (Pre-trained Backbone) ＋ 遷移學習微調 (Transfer Learning)」，並針對影像、聲音與姿態三種專案分別搭載不同的輕量級演算法，讓一般電腦瀏覽器在數十秒內即可完成訓練。

核心關鍵：CNN（卷積神經網路）＋ 遷移學習（Transfer Learning）雙引擎

為何幾十張照片、幾秒鐘就能訓練完成？

Teachable Machine 有用到 CNN（卷積神經網路），而且這正是它能用極少樣本快速訓練出高準確率模型的最大功臣！其底層透過「凍結預訓練 CNN 提取基礎特徵 ＋ 僅訓練末端自訂分類器」的兩階段機制運作：

CNN 特徵提取器（凍結權重）與自訂全連接分類器（微調訓練）資料流圖解
1. 底層架構（CNN 特徵提取器）

處理圖片與音訊專案時，Teachable Machine 內建 Google 預先訓練好的輕量級 CNN 模型（如 MobileNet） 作為「特徵提取器（Feature Extractor）」，負責辨識影像中的線條、形狀、紋理等基礎視覺特徵。

2. 你的訓練過程（自訂分類器）

上傳照片並按下「訓練模型」時，系統會凍結原本 CNN 模型的權重，只針對最後一層的全連接層（Dense / Classification Layer）進行訓練，學習將提取出的特徵對應到你設定的分類標籤（如「貓」或「狗」）。

3. 為什麼這樣設計？

透過「預訓練 CNN ＋ 遷移學習」架構，你不需要準備數十萬張照片，也不需要昂貴的 GPU 伺服器，只要幾十張範例照片，就能在幾秒鐘內於一般瀏覽器上完成訓練並即時推論。

圖解 A：Teachable Machine 多模態遷移學習與微調管線 (Pipeline)

Frozen Backbone + Trainable Custom Head

1. MobileNet 深度可分離卷積

計算量減少 8~9 倍

傳統卷積神經網路（如 VGG、ResNet）在計算時將「空間濾波」與「通道融合」綁在一起，參數量極其龐大。Google 提出的 MobileNet 將標準卷積拆解為兩道輕量化步驟，使模型體積縮小至僅約 5 MB，在瀏覽器中即可達到 30+ FPS 即時推論：

① Depthwise Convolution (逐通道卷積)：每個色彩通道 (R, G, B) 各自使用獨立的 3×3 卷積核進行空間特徵提取，通道彼此間不混合。

② Pointwise Convolution (1×1 逐點卷積)：接著使用 1×1 卷積核在深度方向上進行線性加權組合，將各通道特徵融合成新的特徵圖。

MobileNet 卷積拆解原理圖 (Depthwise + Pointwise)

2. 遷移學習與微調 (Transfer Learning & Fine-Tuning)

小樣本快速收斂

深度學習模型具有階層式特徵表現能力：淺層網路負責辨識通用的「邊緣、紋理、幾何曲線」，越深層才負責組合成「特定物體」。遷移學習微調正是利用這項特性：

🔒 特徵凍結 (Feature Extraction)：保留 MobileNet 在 ImageNet（1,400 萬張圖片、1,000 類）學到的通用視覺知識，將前面數十層卷積層參數「鎖死」，訓練時不修改它們。

🔥 分類頭微調 (Head Fine-Tuning)：移除原本 1,000 類的輸出層，接上針對你專案的新全連接層 (Dense Layer)。透過反向傳播微調這層權重，只需每類 20~50 張照片即可學會全新分類任務。

遷移學習微調 (Fine-Tuning) 權重凍結與更新範圍

3. RNN (循環神經網路) 與聲學時序處理

時間序列記憶

🔄 RNN (Recurrent Neural Network) 記憶迴圈：傳統神經網路每次輸入彼此獨立，而 RNN 擁有隱藏狀態 (Hidden State, ht)，會將前一時間點的記憶資訊迴圈傳遞到下一時間點，讓模型具備「上下文短期記憶能力」。

2. YOLO (You Only Look Once) 核心技術深度解析

Backbone · Neck (FPN+PAN) · Head

傳統雙階段偵測器（如 R-CNN 系列）需先產生數千個候選框再逐一分類，速度極慢。YOLO（你只需看一次）將物件偵測重新定義為單一迴歸問題，只需將整張影像送入神經網路一次前向傳播，就能同時預測出畫面中所有物體的類別機率與精準的邊界框座標 (x, y, w, h)。

圖解 B：現代 YOLO (v8 / v11) 完整三段式偵測管線與 NMS 後處理

Input → Backbone → Neck → Head → NMS

1. 網格劃分與 Anchor-Free 座標迴歸

YOLO 將輸入畫面切分為多個網格（如 80×80、40×40、20×20 三種尺度），物體中心點落入哪個網格，就由該網格負責預測。現代 YOLOv8 / v11 更摒棄了傳統繁瑣的預設錨框 (Anchor-Based)，改採 Anchor-Free 直接預測目標中心點到邊界框四條邊的距離 (l, t, r, b)，大幅提升對不規則形狀物體的泛化能力。

2. Backbone 與 FPN + PANet 雙向特徵金字塔

透過 CSPDarknet / C2f 提取淺層（高解析度、細節豐富）與深層（低解析度、語意明確）特徵，再藉由 FPN（自頂向下）+ PANet（自底向上）雙向融合，使網路同時具備精準框選微小零件與大型物體的能力。

3. IoU 交併比與 NMS (非極大值抑制)

同一個物體常會被相鄰的多個網格同時框出重疊預測框。YOLO 在後處理階段會先保留信心分數最高的框，再計算其餘框與它的 IoU（交集面積 ÷ 聯集面積），只要重疊度超過門檻（如 0.45）便予以剔除，確保每個目標只保留一個最準確的框。

4. Mosaic 資料增強與 CIoU / DFL 損失函數

YOLO 訓練時內建強大的 Mosaic 四圖拼接增強，隨機將 4 張不同場景的圖片縮放拼接成一張，強迫模型在複雜背景中學會辨識小目標；並結合 CIoU Loss 同時考量重疊面積、中心點距離與長寬比，使預測框貼合度達到工業級精度。

資料準備與標註流程深度對比：GTM vs. YOLO

Google Teachable Machine (GTM) 與 YOLO 在資料準備與標註上的核心差異，在於「影像分類（整張圖給一個標籤）」與「物件偵測（框出特定物體位置）」的任務不同，因此兩者的操作流程與複雜度完全不同。

影像分類 · 適合初學者與快速 PoC

1. Google Teachable Machine (GTM)

GTM「資料夾分類法」免拉框示意圖 整張圖 = 單一標籤
資料準備 (Data Preparation)
  • • 資料量：每個類別僅需約 30～100 張 圖片即可運作（官方建議至少 30 張）。
  • • 多樣性：需涵蓋不同角度、光線、背景，並強烈建議建立一個「背景 / 無目標（Background / Nothing）」類別，避免模型在沒有目標時亂猜。
  • • 格式：支援常見圖片格式（JPG, PNG）或直接開啟網路攝影機（Webcam）即時連拍錄製。
資料標註 (Data Labeling)
  • • 無需額外標註工具：採用直覺的資料夾分類法。
  • • 整圖自動標記：在網頁介面上建立不同的 Class（類別），直接將對應圖片上傳或錄製進該類別區塊即可，系統會自動將「整張圖片」視為該類別。
物件偵測 · 工業界與專題首選

2. YOLO (You Only Look Once)

YOLO 人工拉框 (Bounding Box) 標註示意圖 座標 (X, Y, W, H)
資料準備 (Data Preparation)
  • • 資料量：基礎測試每類建議 200～500 張以上；商用高準確率通常需 1,000 張以上。
  • • 資料集切分：必須自行切分為 訓練集 (Train 70-80%)、驗證集 (Val 10-20%) 與 測試集 (Test 10%)。
  • • 環境貼近度：光線、拍攝距離與遮擋情況必須高度貼近實際攝影機畫面。
YOLO 標註檔格式 (.txt) Normalized [0, 1]
# 格式：<類別編號> <中心點X> <中心點Y> <寬度W> <高度H>
0 0.310547 0.520833 0.281250 0.416667
1 0.720112 0.580208 0.250000 0.385417
* 數值皆正規化為 0 到 1 之間，並搭配 data.yaml 指定路徑與類別名稱。

深度解析：為何 YOLO 座標要正規化為 0 ~ 1？

不同攝影機拍出的照片解析度不同（如 1920×1080 與 640×480）。為了讓 YOLO 模型不受圖片大小影響，所有邊界框都必須除以圖片總寬高 (W_img, H_img) 轉換為 0 到 1 之間的相對比例：

實戰避坑指南：GTM 與 YOLO 常見標註地雷與解決方案

Best Practices for High Accuracy
地雷 1：GTM 的「背景偷學」陷阱

若在教室左邊拍「紅圓」、在右邊拍「黑圓」，GTM 模型會偷懶記住背景海報而不是圓形本身！
解法：所有類別必須在相同背景、多種角度與不同光線下拍攝，並加入「純背景 (Nothing)」類別。

地雷 2：YOLO 拉框鬆散或漏標

拉框留太多空白邊緣會導致模型定位不準；同一張圖若有 5 顆紅圓卻只框了 3 顆，漏框的 2 顆會被當成負樣本懲罰模型！
解法：邊界框須緊貼物體邊緣，且畫面中所有出現的目標物必須 100% 全部框出。

地雷 3：樣本不足時的資料增強策略

GTM：內建自動中心裁切為正方形，建議手動在 Webcam 轉動手腕/物體錄製連續影格。
YOLO：可在 Roboflow 開啟 水平翻轉、±15° 旋轉、亮度/對比度微調、Mosaic 拼接，將 200 張原圖擴增為 600+ 張訓練集。
