ESG 智慧工廠實務應用
機電丙級第二題 AI 檢測與動態碳足跡閉環系統

本專案以機電整合丙級第二題「送料與顏色辨識裝配系統」為實體機台藍本，深度整合 C# PC-Based 人機通訊、Google Teachable Machine 機器視覺分類、Node-RED 數據中樞、ISO 14064-1 & ISO 14047 碳數據演算以及 Google Gemini 生成式 AI 設備故障診斷，打造兼具自動化、良率檢測與動態碳管理 (LCA) 的 PDCA 智慧綠色工廠。

實務專題系統數據流向與硬體拓撲（實時動畫）
動畫運行中
藍色：智慧電表功率 / PLC 馬達狀態 (I/O)
綠色：USB 工件影像與 Teachable Machine 辨識結果 / 碳排數據 (AD)
黃色：Gemini 減碳卸載指令與 PLC 氣缸排除控制訊號 (Act)

專案實踐架構

專案開發背景

傳統的機電整合實作僅專注於底層 PLC 與感測器的「順序控制」配線，缺乏與次世代雲端物聯網與人工智慧的鏈接。此外，在淨零碳排與全球供應鏈嚴格碳關稅的要求下，ESG 碳管理已成為企業工廠必備的業務。本專案將最接地氣的「機電丙級第二題實體裝配機台」進行數位化升級，導入邊緣運算與雲端 AI 數據流，實現傳統工控的 ESG 高速轉型。

核心技術亮點

  • PC-Based 軟硬貫通：C# 透過 RS232 通訊控制三菱 PLC 機台。
  • Teachable Machine 機器學習：利用相機即時分類工件材質與表面瑕疵（良品/不良品）。
  • 大數據與物聯網：以 MQTT 協定將高頻能耗與辨識 JSON 封包拋送至 Node-RED。
  • 雙 ISO 碳管理：Node-RED 計算範疇二碳排放，並利用 ISO 14047 生命周期評估（LCA）實時計算鋁合金 vs 塑料工件的原料碳強度。
  • 生成式 AI 閉環：Gemini 自動生成診斷指引，反饋 PLC 控制氣缸。

詳細專題實作步驟說明

Step 1

C# 與三菱 PLC RS232 通訊 & Google Teachable Machine 視覺辨識

此步驟完成機電丙級第二題實體送料裝配台的 PC-Based 控制與 AI 瑕疵檢測。

實作步驟：
  1. PLC 序列配線與設定：送料轉盤馬達由 PLC Y0 驅動，輸送帶馬達由 Y1 驅動，顏色與材質辨識感測器對應 X1 與 X2。
  2. C# PC-Based 通訊開發：C# 使用 `SerialPort` 元件，透過 RS232 串口，以 ASCII 通訊協議（含 CheckSum）每 100 毫秒輪詢 PLC，讀寫 M0（啟動）與 D100（累計產量）。
  3. Google Teachable Machine 影像訓練：
    • 學員開啟 Google Teachable Machine 網站，建立四個圖像分類類別：`金屬良品`、`金屬不良品（表面刮傷）`、`非金屬良品`、`非金屬不良品`。
    • 使用網頁相機拍攝實體工件各 100 張照片，進行線上模型訓練，並匯出模型的 Web API 連結或 TensorFlow.js 權重。
  4. C# 影像辨識與排除控制：C# 呼叫 WebBrowser 或 TensorFlow.NET 加載 Teachable Machine 模型。當相機拍到工件進入檢測區時，進行即時辨識。若偵測為「不良品」，C# 發送 PLC 寫入指令強制將 `Y5 = ON`，驅動實體電磁閥氣缸將不良品推出至廢料槽。
Step 2

MQTT 數據封裝與 Node-RED 中央接收中樞 (IoT 數據傳輸)

將邊緣端機台數據與 AI 推論結果整合，以輕量級物聯網協定傳輸至 Node-RED。

實作步驟：
  1. C# 端 MQTT 用戶端建置：在 C# 專案中透過 NuGet 安裝 `M2Mqtt` 庫，設定連線至本地或雲端 MQTT Broker（如 Mosquitto）。
  2. 數據 JSON 序列化：當裝配台每加工完成一顆工件，C# 將數據封裝成 JSON 格式發布： 
    {
  "timestamp": "2026-08-11T19:22:00Z",
  "foup_id": "foup-9082",
  "material": "metal", 
  "status": "normal",
  "power_kw": 1.85,
  "cycle_time_sec": 12.4
}
  3. Node-RED 數據訂閱：在 Node-RED 拖入 `mqtt in` 節點，訂閱主題 `factory/assembly/data`。
  4. 資料清淤與格式檢查：使用 Change 與 Switch 節點，過濾電表跳點的異常能耗數據，確保後續碳足跡運算正確性。
Step 3

ISO 14064-1 組織級盤查與 ISO 14047 產品生命週期碳足跡演算 (LCA)

於 Node-RED 內建置動態碳管理引擎，實時呈現碳流看板。

實作步驟：
  1. ISO 14064-1 全域變數載入：在 Node-RED 的 Global Context 中存入台電排碳係數（EF = 0.495 kg CO2e/kWh），定時讀取裝配台總能耗計算範疇二排放。
  2. ISO 14047 生命周期評估 (LCA) 計算：
    • 產品生命週期碳足跡公式： \[E_{\text{product}} = E_{\text{material}} + E_{\text{manufacturing}}\]
    • 當工件裝配完成時，Node-RED 依據 C# 傳送的 `"material"` 判定：若為鋁合金，原料碳強度 $E_{\text{material}} = 8.5\text{ kg CO}_2\text{e}$；若為塑料，則 $E_{\text{material}} = 2.1\text{ kg CO}_2\text{e}$。
    • 生產能耗碳排 $E_{\text{manufacturing}} = \text{能耗 (kWh)} \times \text{電力排碳係數 (EF)}$。
    • 利用 Function 節點撰寫 JS 演算法，即時算出每一顆工件的生命週期總碳足跡，並寫入 MySQL 數據庫。
  3. ESG 看板設計：利用 Node-RED Dashboard 繪製出當前良率、累積碳足跡與材質碳強度對比圖表，達到資訊透明化。
Step 4

Google Gemini 生成式 AI 設備異常診斷與抑低控制閉環 (PDCA - Act)

結合大語言模型實現智慧自我診斷，並自動反饋實體機台調控。

實作步驟：
  1. 異常能耗與卡料監測：若裝配台傳回馬達電流過載、连续 3 次工件瑕疵、或單顆碳足跡超出標準值 15% 時，Node-RED 觸發異常警報流。
  2. 呼叫 Google Gemini API：Node-RED 使用 `http request` 節點，打包異常數據向 Google Gemini API 發送 POST 請求，Prompt 如下： 
    [你是一位智慧工廠 ESG 與 PLC 機電顧問]
機電丙級第二題裝配機台發生異常，數據如下：
- 馬達即時能耗: 3.2 kW (標準: 1.8 kW)
- 工件材質: 鋁合金
- 瑕疵狀態: 連續卡料
請用繁體中文在 100 字內說明：可能故障原因與排除步驟，並給出節能減碳的能耗調適指令（例如降低馬達轉速）。
  3. 異常指引與能耗調適自動執行：
    • Gemini 回傳異常報告，Node-RED 自動將「維護指引文字」以 Line Bot 拋送給現場工程師。
    • 同時，Node-RED 解析 Gemini 的調適指令，自動以 MQTT 發送控制命令 `{"command": "slow_down_motor", "speed_hz": 30}` 給 C# 中控程式。
    • C# 接收後，自動透過 RS232 寫入 PLC 暫存器（改變變頻器頻率），放慢送料轉盤與輸送帶速度以降低功耗，實現 PDCA 自動閉環改善！

專題成效與學習成果

學員學習成果

完成本專題後學員將具備之能力
  • 軟硬體整合力：完整實作從三菱 PLC 配線、暫存器規劃、C# HMI 到 PC-Based RS232 雙向通訊。
  • AI 開發力：掌握 Google Teachable Machine 視覺訓練、模型匯出及 C# 影像串接，並熟練雲端 Gemini 大語言模型 API 串接。
  • ESG 工業物聯網：掌握 ISO 14064-1 & 14047 的過程方法，並能在 Node-RED 中建立動態碳管理運算與 PDCA 控制閉環。

綠色智慧工廠效益

專案導入後的產線優化指標
  • 良率提升 18%：透過相機與 Teachable Machine 進行雙重表面瑕疵檢測，大幅降低出貨不良率。
