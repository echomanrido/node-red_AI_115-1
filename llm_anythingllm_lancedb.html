AnythingLLM + LanceDB
企業私有知識庫與向量檢索實戰指南

為工業企業打造徹底離線、安全無虞的私有 AI 助手！從 AnythingLLM 桌面版安裝、工作區 (Workspace) 權限劃分、多格式文件解析 (PDF/Word/TXT/網頁爬蟲)、內建高效 LanceDB 向量資料庫儲存與比對、@agent 智慧代理人調用技能，到透過 REST API 實現程式自動化問答串接！

1

AnythingLLM 安裝與核心服務選型

1.1 下載與安裝

至官方網站 anythingllm.com 下載 Windows 桌面版安裝檔，安裝後開箱即可運行，免去繁瑣的 Python 虛擬環境配置。

1.2 初始引導精靈配置（三大關鍵提供者）

  • LLM Provider (語言大模型)：選擇本地 Ollama（預設網址 http://127.0.0.1:11434），模型選擇拉取好的 gemma2:9b 或 llama3.2。
  • Embedding Engine (向量嵌入引擎)：向量模型負責將文章切片轉換成高維數學向量。推薦選用 Ollama (nomic-embed-text) 或 AnythingLLM Native Embedder，運算極快且完全在本地執行。
  • Vector Database (向量資料庫)：強烈推薦選擇 LanceDB。
為什麼首選 LanceDB？
傳統向量庫（如 Milvus、Qdrant）需要架設伺服器或 Docker 容器；而 LanceDB 是以檔案為基礎的無伺服器 (Serverless) 嵌入式向量資料庫，直接存放於本機目錄，支援萬筆向量毫秒級餘弦相似度 (Cosine Similarity) 檢索，零維護負擔！
企業私有 RAG (檢索增強生成) 數據流向四部曲
2

工作區 (Workspace) 建立、文件解析與切分

2.1 建立工控專屬工作區

在左側點選「+ New Workspace」，命名為 factory-sop（設備故障排查專區）。每個工作區擁有獨立的上下文提示詞、檢索閾值與專屬向量文件庫。

2.2 文件上傳與 Chunking 切分參數

點擊工作區上方的上傳圖示，將 機台故障-常見處理流程.txt 或 PLC操作手冊.pdf 拖入視窗：

  • Text Splitter (切分器)：系統自動將長文依段落切成小區塊 (Chunks)。
  • Chunk Size：建議設為 500 ~ 1000 tokens，確保每個區塊具備完整語意。
  • Chunk Overlap (重疊率)：設為 10% ~ 15%，防止關鍵句子剛好被邊界刀切斷。

上傳完畢後，勾選文件並點擊 「Move to Workspace」➔「Save and Embed」，系統即啟動向量模型將切片轉換為高維座標寫入 LanceDB！

AnythingLLM LanceDB Agent

根據 《機台故障-常見處理流程.txt》 第 3 節說明，主軸運轉溫度過高之處置 SOP 如下：

  1. 立即切換至手動模式：按下控制面板暫停鍵，停止進刀。
  2. 檢查冷卻循環液：確認冷卻水箱液位是否低於下限標線，並檢查循環幫浦壓力是否維持在 0.3~0.5 MPa。
  3. 清理散熱濾網：檢查主軸馬達散熱風扇與防塵濾網是否堆積油泥，必要時進行更換。

3.2 點擊即看原文引用 (Citations)

每次模型回答完畢，下方會列出 Sources (1) (2)，點開即可直接查驗引用自手冊的第幾頁或哪一段文字，徹底杜絕 AI 幻覺！

3.3 @agent 智慧代理人模式

在輸入框輸入 @agent，AI 將化身為具備 Tool Use (工具調用) 能力的智能體，支援：

  • Web Browsing：自動根據問題連網爬取目標網頁解析。
  • SQL / LanceDB 精準搜尋：跨多份文件比對零件庫存或設備料號。
  • Speech-to-Text：按住麥克風直接講國語，內建語音辨識直接轉成文字提問。
4

AnythingLLM REST API 程式自動化串接

AnythingLLM 支援完整開發者 API，可讓 C#、Python 或 Node-RED 程式直接調用企業知識庫：

4.1 取得 API Key

進入 AnythingLLM 左下角 Settings ➔ Tools ➔ Developer API，點擊「Generate API Key」取得金鑰字串。

4.2 cURL 測試查詢工作區對話

# 查詢工廠工作區 (Slug: factory-sop) curl -X POST "http://localhost:3001/api/v1/workspace/factory-sop/chat" \ -H "Authorization: Bearer YOUR_API_KEY_HERE" \ -H "Content-Type: application/json" \ -d '{ "message": "根據常見故障處理流程，設備運轉時溫度過高應該如何處理？", "mode": "query" }'

4.3 Node-RED 實作流範例：

// Node-RED Function 節點程式碼 msg.headers = { 'Authorization': 'Bearer 7B8F9A-4C2D-8812-YOURKEY', 'Content-Type': 'application/json' }; msg.payload = { message: `機台異常警報: 輸送帶馬達伺服過載，請列出標準 SOP 檢查清單。`, mode: "query" }; return msg; // 後接 [http request] 節點： // 方法: POST // URL: http://localhost:3001/api/v1/workspace/factory-sop/chat
