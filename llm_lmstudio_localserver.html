LM Studio (Local Server)
地端模型工作站與 API 伺服器架設指南

探索目前全球開發者公認最友善的圖形化本地大模型工作站 LM Studio！從軟體安裝、Hugging Face GGUF 各級量化版本下載、顯卡 GPU 層數卸載 (GPU Offload) 極速調校，到一鍵啟動 100% 相容 OpenAI REST API 規格 的本地推論伺服器 (Port 1234)，讓 C#、Python 與 Node-RED 零成本切換地端推論！

1

LM Studio 安裝與 GGUF 量化模型下載

1.1 下載與跨平台安裝

至官方網站 lmstudio.ai 下載 Windows 安裝檔。LM Studio 內建 llama.cpp 高效推論核心，原生支援 NVIDIA CUDA、AMD ROCm 以及 Apple Metal 硬體加速。

1.2 搜尋與 GGUF 量化等級選型心法

點擊左側「搜尋放大鏡」圖示，即可直接檢索 Hugging Face 上的開源模型（如 Qwen2.5-Coder-7B-Instruct-GGUF、Meta-Llama-3.1-8B-Instruct-GGUF）。

量化等級 (Quantization)模型大小壓縮比推論品質損失適用硬體推薦
Q4_K_M (強烈推薦) 約原模型 1/4 大小 (~4.5 GB) 極微小 (Perplexity 幾乎無差) 8GB 顯卡 (RTX 3060 / 4060) 最佳性價比首選
Q5_K_M 約原模型 1/3 大小 (~5.5 GB) 更低損失、邏輯推理更紮實 適合 12GB 顯存主機
Q8_0 約原模型 1/2 大小 (~8.5 GB) 接近無損 16-bit 表現 適合 16GB ~ 24GB (RTX 4090) 追求極致精準度
2

硬體加速 GPU Offload 與推論參數深度調優

2.1 GPU 層數卸載 (GPU Acceleration / Offload)

在模型載入設定面板（右側），找到 GPU Settings：

  • 勾選 GPU Offload。
  • 將拉桿推到最大（例如 33 / 33 Layers），將神經網絡所有計算層全數載入獨立顯卡的 VRAM 中。
  • 推論速度成效：純 CPU 計算約 5~8 tokens/sec，全進 GPU 後可瞬間飆升至 45~75 tokens/sec，達到即問即答的極致流暢度！

2.2 核心生成參數詳解

  • Context Length (上下文長度)：預設為 2048 或 4096，可調高至 8192 或 16384 以分析長篇配線圖與代碼。
  • Temperature (隨機度)：工控設備排查或編寫 PLC 代碼時，建議設定為 0.1 ~ 0.3，確保回答嚴謹一致，避免隨機猜測。
  • Repeat Penalty (重複懲罰)：設為 1.1，有效防止小模型陷入迴圈重複講同一句話的窘境。
3

一鍵啟動 OpenAI 相容 Local Server (Port 1234)

LM Studio 最強大的功能即為內建100% 相容 OpenAI REST API 規格的本地 HTTP 伺服器：

點擊左側雙箭頭圖示（Local Server 分頁），在頂部選定剛才下載的模型，點擊綠色 「Start Server」！伺服器將在 http://localhost:1234 啟動。

3.1 cURL 測試模型列表端點

# 取得當前伺服器運行的模型 curl http://localhost:1234/v1/models

3.2 cURL 測試 Chat Completion 端點

curl http://localhost:1234/v1/chat/completions \ -H "Content-Type: application/json" \ -d '{ "messages": [ {"role": "system", "content": "你是一位機電與 PLC 自動化專家，用繁體中文回答。"}, {"role": "user", "content": "Modbus TCP 的 MBAP Header 包含哪四個欄位？"} ], "temperature": 0.2, "max_tokens": 500 }'
4

程式無痛切換：Node-RED & C# 串接地端 LM Studio

4.1 原本寫 OpenAI 雲端 API 的程式碼，如何 1 秒改為地端？

只要將 API Base URL 由 https://api.openai.com/v1 改為 http://localhost:1234/v1，API Key 填入任意非空字串（如 not-needed），所有現有程式碼完全不需要改寫！

工控邊緣端：Node-RED 與 LM Studio 本地端 0 延遲閉環架構

4.2 Node-RED 實作流範例：

// Node-RED Function 節點程式碼 msg.headers = { 'Content-Type': 'application/json' }; msg.payload = { messages: [ { role: "system", content: "你是一位智慧工廠機電維護助理，請簡短用繁體中文條列排查步驟。" }, { role: "user", content: `產線警報: 機台編號 M-05，伺服驅動器顯示警報代碼 AL-03，可能原因與處置？` } ], temperature: 0.2 }; return msg; // 後接 [http request] 節點： // 方法: POST // URL: http://localhost:1234/v1/chat/completions

4.3 效能即時監控面板

在 LM Studio 的 Local Server 介面下方，有即時的 Tokens/sec 儀表與 GPU VRAM 佔用率。若發現推論速度驟降，可隨時降低 Context Length 或改載入更輕量的量化版本。
