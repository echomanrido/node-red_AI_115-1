為什麼需要設定 root@% 遠端連線？

MySQL 預設安裝後，root 帳號通常僅允許從本機（localhost）登入。在專題開發（例如 PLC 資料收集、跨電腦前端/後端串接、物聯網設備寫入資料庫）時，我們需要透過 MySQL Workbench 的 Users and Privileges 將允許連線的主機設為萬用字元 %，代表允許來自任何 IP 位址的遠端連線。

本單元重點參數摘要

管理功能位置 Users and Privileges
Login Name root
Authentication Type caching_sha2_password
Limit to Hosts Matching %

投影片畫面互動模擬器 (MySQL Workbench)

點擊畫面上的橘色標記 1 ~ 6 查看投影片各欄位說明，或切換至「實作練習模式」親手設定。

實作任務：請完成投影片中的 root@% 遠端連線設定

請依序：1. 點擊左側「Users and Privileges」 ➔ 2. 選擇或設定 Login Name 為 root ➔ 3. 將 Limit to Hosts Matching 設為 % ➔ 4. 輸入一致的 8 位以上密碼並點擊右下角「Apply」。

Administrative Roles (管理角色權限)

如果是新增的 root@% 帳號，別忘了在 Administrative Roles 勾選 DBA（或全選所有權限），並點擊右下角 Apply，否則遠端登入後會看不見其他資料庫！

重點標記 #5

Limit to Hosts Matching: %

這是允許遠端連線最關鍵的設定欄位！預設的 localhost 只允許資料庫所在的那台電腦自己連線；將其改為萬用字元 %，即代表允許任何 IP 位址的主機連入此 MySQL 伺服器。

實務補充技巧：

若專題在固定區域網路（例如教室或工廠內網 192.168.1.%），也可以填入 192.168.1.% 來限制只有同網段的 PLC 或電腦可以連入，兼顧便利與資安。

快速切換畫面部位解說：
即時對應 SQL 語法預覽 
-- 儲存設定時 Workbench 執行的等效 SQL：
ALTER USER 'root'@'%'
IDENTIFIED WITH caching_sha2_password
BY 'RootPassword123!';

GRANT ALL PRIVILEGES ON *.* TO 'root'@'%' WITH GRANT OPTION;
FLUSH PRIVILEGES;

標準操作步驟詳解 (Step-by-Step)

依照投影片中的設定畫面，在 MySQL Workbench 開放 root 遠端連線只需 4 個步驟：

STEP 01

進入使用者與權限管理

開啟 MySQL Workbench 並連入伺服器（投影片範例連線名稱為 PLC），於左側 Navigator 面板的 MANAGEMENT 區塊點擊 Users and Privileges。

對應畫面標記 #1
STEP 02

選取或新增 root 帳號

在中間 User Accounts 清單檢視 root 帳號的 From Host 欄位。若只有 localhost，可點選它直接修改，或點擊下方 Add Account 建立遠端專用帳號。

對應畫面標記 #2、#3
STEP 03 (核心重點)

設定萬用字元 %

在右側 Login 頁籤中，確認 Login Name 為 root，並將 Limit to Hosts Matching 改為 %（代表允許任何外部 IP 連線）。

對應畫面標記 #5
STEP 04

確認密碼、權限並儲存

在 Password 與 Confirm Password 輸入密碼，若為新增帳號請至 Administrative Roles 勾選 DBA 權限，最後點擊右下角 Apply 即完成。

對應畫面標記 #4、#6

From Host 萬用字元與驗證方式比較

Limit to Hosts 設定值 代表意義與適用情境
% 允許任何主機連線（投影片設定值）。適用於專題開發、跨網段測試或浮動 IP 環境。
localhost / 127.0.0.1 僅允許本機連線。外部電腦、PLC 或其他設備皆無法連入（例如投影片中的系統預設帳號 mysql.sys）。
192.168.1.% 允許特定區網段連線。% 可搭配網段使用，限制僅 192.168.1.0 ~ 255 的設備可連線。
192.168.1.10_ 單一字元萬用字元 _。代表僅匹配 192.168.1.100 ～ 192.168.1.109。
為什麼投影片中 Authentication Type 是 caching_sha2_password？

自 MySQL 8.0 起，預設的密碼加密驗證外掛改為安全性更高的 caching_sha2_password。若您的專題使用較舊版的 PLC 通訊模組、Node-RED 舊套件或舊版驅動程式連線時出現 Authentication plugin 'caching_sha2_password' cannot be loaded 錯誤，可將此下拉選單改為 Standard (mysql_native_password)。
