逆向調查與重構的能力

REA (Reverse Engineer Anything) 透過 Model Context Protocol (MCP) 連接 Claude Code、Cursor、Gemini CLI 等大模型智能體與專業逆向分析工具，在缺乏原始碼的情況下調查功能機制、出示完整證據鏈，並在您的專案中乾淨重構。

產生逆向 Prompt 檢視快速安裝
$ npx rea-agents setup

支援 Claude Code、Cursor、Codex、Gemini CLI 自動偵測註冊

REA 核心架構與工作原理

不是單純的靜態反編譯工具，而是建立在「證據導向」的工作流。

01

自然語言引導提問

開發者向支援 MCP 的 AI Agent（如 Claude 或 Cursor）發出任務：「我想知道某 Electron 應用的剪貼板 Bridge 是如何實現的」。

02

REA 工具自動取證

Agent 經由 MCP 調用本機 REA 分析器，針對 ASAR、二進位二級符號、IPC 通道或封包進行靜態與動態檢查，收集確鑿代碼證據與限制條件。

03

生成重構實作與測試

Agent 依據 REA 回傳的證據鏈進行邏輯復原，為您的目標專案產出 Clean-room 原創代碼，並建立測試用例進行對比驗證。

Getting Started

完整安裝與環境配置

REA 需要 Node.js 22.x (>=22.19), 24.x, 或 26+ 以及 npm。分析全部在本機安全環境執行。

步驟 1：智能體一鍵註冊 npx (推薦)

在終端機中執行 setup 命令，會自動偵測您的 Claude Code、Cursor、Gemini CLI 等並掛載 REA MCP 服務：

npx rea-agents setup

完成授權後，請務必重新啟動您的 AI Agent 終端或 IDE 視窗。

步驟 2：全域 CLI 安裝（可選） npm global

如果您偏好直接在命令列執行靜態分析指令，可以全域安裝 CLI：

npm install --global rea-agents
檢查版本： rea --version 升級： rea update
步驟 3：後端反編譯引擎支援 Native Providers

分析原生二進位程式碼（Native Binaries）時，建議本機具備下列之一：

  • Ghidra (開源首選)：支援 x86, ARM, 16-bit DOS，需 Java 17+。
  • Hopper Disassembler：macOS / Linux 輕量原生反編譯。
  • IDA Pro：透過 IDA 提供方介面連接。
  • JADX / TShark：針對 Android APK 或 pcap 網路包分析。
claude_desktop_config.json 或 settings.json

若手動註冊 Claude Desktop 或 Cursor 的 MCP 伺服器，可將以下設定填入配置檔中： 

{
  "mcpServers": {
    "rea": {
      "command": "npx",
      "args": [
        "-y",
        "rea-agents@latest",
        "serve"
      ],
      "env": {
        "REA_ANALYSIS_WORKSPACE": "./.rea_cache"
      }
    }
  }
}

💡 實用提示：

使用 npx rea-agents setup 時，安裝腳本會自動備份既有的配置檔案，並將 REA 的技能設定（Skill Guide）直接注入 Agent 上下文中。

Coverage

支援分析的目標格式與回傳資訊

REA 會將複雜的二進位或打包檔案轉化為 LLM 能夠理解的高價值結構化資料。

JavaScript & Electron

檢查解包後的目錄或 .asar 檔案。

回傳：模組相依圖、IPC Channels、Preload 腳本、Source Maps、原生 Node 模組關聯。
工具：本機 Node.js 與內建 AST 解析器

原生二進位檔案 (Native)

Mach-O (macOS)、ELF (Linux)、PE/DLL (Windows)。

回傳：偽代碼 (Decompiled C)、彙編代碼、字串常數表、導出符號與交叉引用 (Xrefs)。
工具：Ghidra、Hopper 或 IDA

網路封包與通訊協議

HAR 檔案、mitmproxy capture、Wireshark pcap。

回傳：API 端點清單、Payload 結構、TLS SNI、重複參數分佈與狀態轉換規則。
工具：TShark 4.x / mitmdump

.NET 託管組件

C# 與 .NET Framework / .NET Core 組件。

回傳：中繼資料、CIL 中間語言指令、宣告的原生 DLL 依賴與組建版本比對。
工具：靜態組件檢查引擎

Android APK & 資源

Android Package、DEX、AXML 資源。

回傳：Manifest 清單權限、反編譯 Java/Kotlin 類別、字串資源表、Flutter Dart 快照資訊。
工具：Headless JADX + Apktool

進程運行時追蹤 (Runtime)

針對正在運行的行程或腳本執行行為觀測。

回傳：終端輸出串流、PTY 互動事件、檔案系統讀寫觀測與行程退出狀態比對。
工具：Linux/macOS 原生 PTY 隔離沙盒

工程倫理與 Clean-Room（淨室設計）原則

          

            REA 的價值在於「理解架構」與「取得證據」，而非複製受版權保護的原始代碼。在進行商業相容性重構時，建議遵循淨室設計流程：由 Agent 產出架構規格與行為說明書，再由另一環境撰寫全新實作，以確保合法合規。
