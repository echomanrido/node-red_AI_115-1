痛點警示 • Legacy Training Data

為什麼 AI 寫的網頁只過一半（$53\%$）？

雖然現在許多開發者都直接讓 AI 寫網頁，但實測下來平均卻只過了一半的檢查項目。根本原因在於：AI 的訓練資料往往停留在好幾年前的舊程式碼！

  • ✕ 無視瀏覽器內建新功能：現代瀏覽器早已提供原生的宣告式 API 與 CSS 機制，AI 卻不知道或不敢用。
  • ✕ 暴力重造輪子：習慣從頭手刻幾百行繁瑣的 JavaScript 事件監聽與動畫計算，導致效能低落與相容性問題。
  • ! 基準及格率偏低：在 200 多題現代網頁標準測試中，未掛載指南的 AI 基準通過率僅有 $P_{\text{base}} = 53\%$。
核心機制 • Modern Web Guidance 1.0

讓 AI 動手前先翻閱的專家工具書

Google Chrome 團隊推出的免費開源專案 Modern Web Guidance 1.0，核心設計非常直接：在 AI 開始寫程式前，強制要求它先查閱對應領域的最新最佳實踐。

  • ✓ 200 多篇專家指南：涵蓋版面、動畫、互動元件、效能與無障礙等領域的標準寫法。
  • ✓ 對照 Baseline 跨瀏覽器清單：自動核對哪些現代功能已在各大瀏覽器穩定支援。
  • ✓ 舊瀏覽器替代備案（Fallback）：在採用新 API 的同時，自動為舊版環境準備漸進增強的替代方案。

實測成效與 Token 成本權衡

在超過 200 題的公開基準評測中，裝載 Modern Web Guidance 1.0 後，網頁檢查通過率從 $53\%$ 躍升至 $92\%$。但因為 AI 必須額外閱讀指南並進行規格比對，Token 消耗量也會隨之增加：

1. 檢查通過率絕對提升與相對增幅
$$\Delta P = 92\% - 53\% = +39\% \quad \left(\frac{92 - 53}{53} \approx +73.6\%\right)$$
2. 各工具 Token 消耗成本倍率
$$\text{Cost}_{\text{Claude Code}} = 1.3\times \ (+30\%), \quad \text{Cost}_{\text{Codex}} > 2.0\times \ (>+100\%)$$
結論：以可控的 Token 成本換取高品質交付

生態系與開源策略 • Cross-Browser Neutrality

為什麼 Google 選擇免費開源並聯手競爭對手？

1. 競爭關鍵轉向「品質」而非「速度」

官方指出，當所有人都開始用 AI 寫程式後，產出速度已經不再是稀缺優勢，誰能寫出更穩定、相容性更好、體驗更流暢的高品質網頁，才是真正的決勝點。

2. Chrome 聯手 Edge、Firefox 與 MDN 共同維護

這套指南並非 Chrome 閉門造車，而是找來 Microsoft Edge、Firefox 以及 MDN 共同參與維護，確保推薦的每一項技術規範都具備跨瀏覽器中立性。

3. 創作者深度解讀：未來寫網頁的是 AI

「因為未來主要寫網頁的是 AI——如果 AI 不會用瀏覽器的新功能，那就等於根本沒人用！」唯有將這套指南完全免費開源，才能讓市面上所有主流 AI 工具都納入採用，推動整個 Web 生態向前演進。
