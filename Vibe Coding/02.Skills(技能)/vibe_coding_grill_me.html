Vibe Coding 是將直覺與靈感迅速化為原型的「油門」；
而 Grill Me 是主動把提問權交給 AI，以資深架構師與資安官視角逼出盲點的「煞車與方向盤」。

Vibe Coding 是什麼？

直覺流開發 • 創新加速器 🚀

由 Andrej Karpathy 等人推廣的新興哲學。開發者專注於提供願景、意圖與感覺（Vibe），將繁複的語法、套件安裝與樣板代碼完全委由 AI 即時生成。

  • 極速驗證想法，原型（MVP）數小時內成型
  • 保持無阻礙的沉浸式創作心流 (Creative Flow)
  • 盲點：容易積累脆弱架構、幻覺代碼與安全漏洞

Grill Me Skill 是什麼？

控制反轉 (IoC) • 殘酷審問官 🛑

源自 Matt Pocock 的 AI 技能規範：「停止迎合我，請像最嚴格的主架構師一樣無情拷問我（Grill Me）」，主動尋找邊界條件與潛在災難。

  • 控制反轉（Inversion of Control）：AI 主動提問，人類做決策
  • 在敲下一行代碼前，先剷除 90% 的架構隱患
  • 生成鋼鐵般穩固的規格書 (SPEC.md) 與架構紀錄 (ADR)
WINDOWS & GOOGLE ANTIGRAVITY SPEC

Google Antigravity 安裝與指令指南 (Windows)

專為 Windows 10/11 (PowerShell / Command Prompt) 環境設計的 Skill 載入規範

Matt Pocock / skills RobMitt / grill-me-skill
Windows 安裝範疇：

Windows PowerShell 全域一行安裝指令

%USERPROFILE%\.agents\skills\grill-me\SKILL.md

按下鍵盤 Win + X 選擇 Windows PowerShell，貼上以下指令即可自動建立目錄並下載 Matt Pocock 原生規範：

# 建立全域技能目錄並拉取 SKILL.md 規格
$p = Join-Path $env:USERPROFILE '.agents\skills\grill-me'
New-Item -ItemType Directory -Force -Path $p
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/mattpocock/skills/main/skills/grill-me/SKILL.md' -OutFile (Join-Path $p 'SKILL.md')

專案級 (Workspace Scope) 安裝指令

.\.agents\skills\grill-me\SKILL.md

在您的專案根目錄開啟 PowerShell 執行，該設定可提交至 Git，讓團隊所有 Antigravity 使用者同步享有此規範：

# 於當前專案工作區安裝
New-Item -ItemType Directory -Force -Path '.\.agents\skills\grill-me'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/mattpocock/skills/main/skills/grill-me/SKILL.md' -OutFile '.\.agents\skills\grill-me\SKILL.md'
01

觸發審訊 (IoC 啟動)

/grill-me [你的想法草稿]

告知 Antigravity 暫停自動寫碼，進入「控制反轉模式」。Agent 會分析想法並提出第一波前沿質詢。

★ 回答只需簡答：如「1 選 A，2 改用 JWT」
02

結合現有代碼庫審查

/grill-with-docs

命 Antigravity 深入閱讀工作區內的現有檔案、資料庫 Schema 與 API 規格，針對系統擴展性與安全性深挖破綻。

★ 自動過濾現有已實現模組，不重複質疑
03

規格落地與自主執行

/goal 生成 SPEC.md 並實作

審問完成後，命令 Antigravity 將決策凝結成規格書，並啟動 Autonomous ReAct 迴圈進行無瑕疵代碼生成。

★ 一次跑通，重構成本大幅降為 0

01. 架構防暴走 (System Architecture)

阻絕過度設計與效能黑洞

我打算用 Vibe Coding 打造以下功能： [在此填入你的產品或模組想法] 在寫任何代碼前，請完全放下討好心態，扮演 Google Staff Engineer。 請深入審視並對我發動 Grill Me： 1. 列出 3 個最容易引發效能瓶頸或過度工程（Over-engineering）的盲點。 2. 指出並行（Concurrency）、網路瞬斷或狀態不同步時可能出現的毀滅性 Bug。 3. 每次提出 1~2 個關鍵問題，並附帶建議選項供我選擇。Grill me!
適用：專案啟動、狀態管理規劃與資料流設計。
02. 白帽資安稽核 (Security Auditor)

全面獵殺 XSS、注入與權限繞過

請扮演資深滲透測試專家與資安審計官。 針對我即將實作的這個模組： [貼上你的 API 規格或資料操作邏輯] 請無情拷問我以下資安維度： - 使用者輸入如何惡意繞過前端防禦？ - API 端點是否存在物件層級授權漏洞（BOLA）或速率未限制風險？ - 敏感 Token / Key 是否有外洩風險？ 請提出 3 個最致命的攻擊向量，並逼我說明防禦策略。
適用：包含認證、金流或使用者輸入之功能。
03. 邊界條件極限測試 (Chaos Testing)

擊碎 Happy Path 的虛假繁榮

這是我即將交付的程式邏輯與流程設計： [貼上流程或功能說明] 請扮演 Chaos Engineer。請列出 3 個我絕對沒想到的極端狀況（Edge Cases）： 1. 用戶在按鈕送出瞬間斷網或狂按 10 次。 2. 伺服器返回 500 或格式損毀的 JSON。 3. 本地儲存配額已滿時的例外捕捉。 請質問我目前的 UI 與狀態機該如何平穩優雅降級（Graceful Degradation）。
適用：進入 Code Review 與 Commit 前把關。
04. MVP 砍功能極簡版 (Brutal PM)

狠心砍除 80% 假需求

我現在規劃了這堆功能清單： [貼上完整功能清單] 請扮演極度崇尚精益創業（Lean Startup）的冷酷 PM。 請質問我： - 這其中哪一項是核心假設？哪三項是自嗨的「鍍金功能（Gold Plating）」？ - 如果只給我 2 小時上線驗證，我該砍掉哪些東西？ 逼我做出取捨，幫我鎖定出最小可生存版本（MVP）。
適用：剛有靈感，想快速推出第一版原型時。
