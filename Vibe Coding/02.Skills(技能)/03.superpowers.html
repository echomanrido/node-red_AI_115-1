Superpowers 是為 AI 程式代理 (如 Claude Code、Cursor、Windsurf) 打造的技能方法論。以 TDD、架構拆解、Git 隔離與證據先行原則，杜絕幻覺與假綠燈。

4 大關鍵必備指令：執行過程與中繼產物

這是 Superpowers 軟體工程的核心脊椎。點擊切換查看各指令的標準執行步驟、產生檔案清單與中繼產物範本。

五階段標準軟體工程管線

從模糊需求到上線驗證，嚴格遵循單向推進與回滾規範

PHASE 01

需求頭腦風暴

一次只問一個關鍵問題，梳理架構取捨與邊界條件，產出規格書。

產物: specs/*.spec.md
PHASE 02

微步計劃拆解

將規格切分為 ≤15 分鐘的微任務，指定明確驗證命令與勾選單。

產物: plans/*.plan.md
PHASE 03

TDD 隔離實作

Red ➔ Green ➔ Refactor 循環，在獨立 Git Worktree 中撰寫代碼。

產物: tests/*.test.ts
PHASE 04

派遣獨立審查

派遣專門 Reviewer Agent，檢視架構、覆蓋率、嚴謹處理每一條反饋。

產物: .review/feedback.md
PHASE 05

實證完成收尾

終端實測無報錯才算完成；合併或提 PR，清理 worktree 與中繼檔。

產物: Clean Git Branch / PR

             Antigravity 核心理念
          

          
為什麼 AI 程式設計需要「重力與約束」？

          

            LLM 的本性是「討好用戶」與「過度樂觀跳步」。未加約束的 Agent 往往會直接生成未經測試的大量代碼，產生假綠燈和難以追蹤的架構負債。
          

        


        

          
          

            

              
              盲目 Vibe Coding（失控模式）
            

            
    
              
  • 
                
                未定義邊界就直接敲業務代碼，反覆踩中隱藏 bug。
              
    • 
              
  • 
                
                先寫實作代碼再「補測」，製造出永遠為真、毫無檢驗力的假測試。
              
    • 
              
  • 
                
                在主分支直接大幅改動，缺乏 git worktree 隔離，難以安全回滾。
              
    • 
              
  • 
                
                Agent 口頭聲稱「已修復完畢」，實際運行卻直接拋出 TypeError。
              
    • 
            

          


          
          

            

              
              Superpowers 規範模式（嚴謹工程）
            

            
    
              
  • 
                
                先寫規格書：透過頭腦風暴敲定 edge cases，獲得同意後才動工。
              
    • 
              
  • 
                
                嚴格 TDD：先寫測試並親眼在終端看到紅燈報錯，再填寫最簡通過代碼。
              
    • 
              
  • 
                
                Worktree 隔離：所有特性在專屬 worktree 進行，保持 main 永遠可發布。
              
    • 
              
  • 
                
                證據先行：沒跑測試指令並擷取終端輸出前，禁止宣布「任務完成」。
