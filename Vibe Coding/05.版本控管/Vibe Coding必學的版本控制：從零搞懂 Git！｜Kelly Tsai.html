痛點解析：為什麼 Vibe Coding 需要版本控制？

💥 沒有版本控制的四大慘劇

  • ✕ 拆東牆補西牆：請 AI 修正按鈕樣式，結果連資料庫連線與登入邏輯一起被改壞。
  • ✕ Ctrl+Z 的極限：一旦關閉編輯器或跨越多個檔案修改，復原鍵完全失效，只能痛苦重來。
  • ✕ 資料夾命名地獄：電腦裡充滿 專案_final_v2_真的最終版，根本分不清哪版能動。
  • ✕ 本機單點風險：檔案全鎖在自己電腦裡，換台電腦無法繼續開發，也無法安全地與隊友協作。

📐 版本控制狀態演進與回溯成本模型

KaTeX 建模

在 Git 的世界裡，每次執行「蓋章存檔（Commit）」，都是將前一刻專案快照 $S_{t-1}$ 加上本次 Diff 程式碼變更集 $\Delta C_t$，推進至下一個不可竄改的確定狀態：

$$S_{t} = f(S_{t-1}, \Delta C_t), \quad \forall t \in \mathbb{N}$$

當你開闢一條新分支（Branch）進行 AI 實驗時，其狀態空間與主線完全正交隔離（$B_{\text{feature}} \perp B_{\text{main}}$）。一旦改壞需要回溯，透過 Commit Hash 還原 $\text{Restore}(H_i) \rightarrow S_i$ 的時間複雜度遠勝無版控的人工反覆修復：

有 Git 存檔點
$O(1)$ 瞬間退回
$\text{Restore}(H_i) \rightarrow S_i$
無版本控制
$O(n \cdot k)$ 發散迴圈
反覆請 AI 猜測修補 $n$ 檔
⚠️

Vibe Coding 避坑提醒：讓 AI 大改前，務必先開 Branch！

永遠不要在你的主線（main）上直接下複雜的 Prompt 讓 AI 重構整個專案！先用 git checkout -b 開一條平行宇宙分支；改成功了就 Merge 回主線，改壞了直接整條分支刪除，主線毫髮無傷。

核心觀念：Git 跟 GitHub 到底差在哪？

💻 Git（本地端的記帳方法）

安裝在你自己電腦裡的「版本控制工具」。它就像一本專屬帳本，忠實記錄「誰在什麼時候、把哪幾行程式碼改成了什麼」，即使沒有網路也能隨時存檔與退回。

☁️ GitHub（雲端網站平台）

把你電腦裡的檔案連同這本「Git 帳本」一起備份到雲端的網站。免費帳號就能建立私人專案（Private Repo），方便跨裝置同步、雲端部署或團隊審核。

🔖

Commit（蓋章存檔）

就像玩遊戲打 Boss 前按下的「手動存檔點」。每次 Commit 都會產生一組獨一無二的編號（Hash）與說明文字，確保未來隨時能精準跳回這一刻。

🌿

Branch & Merge（平行宇宙）

從 main 主線分岔出一條獨立時空。在分支上放手讓 AI 實驗新功能，測試沒問題後再透過 Merge 合併回主線。

🔍

Pull Request (PR) & Diff

合併回主線前的「正式審核單」。GitHub 會用 Diff 畫面標出改動：綠色代表新增、紅色代表刪除，一眼抓出 AI 是否偷刪重要程式碼。

✅

最佳實踐：何時該 Commit？如何寫好 Commit Message？

  • 存檔時機黃金法則：只要程式處於「還能正常跑起來」的狀態，就要立刻 Commit！因為 AI 修改幅度大，密集存檔點能把損失降到最低。
  • 寫人看得懂的說明：拒絕寫「更新」、「改了一下」這種無意義留言。應該具體寫出做了什麼，例如："修好登入後跳轉失敗的問題" 或 "新增深色模式切換按鈕"。
🚨

資安警告：用 .gitignore 保護 API Key 與機密金鑰！

Vibe Coding 經常會用到 OpenAI、Claude 或資料庫的 API Key（通常放在 .env 檔案中）。千萬不要把金鑰推送到 GitHub，否則一旦設為公開，幾秒內就會被爬蟲盜刷帳單！請務必建立 .gitignore 檔案並將 .env 列入排除名單，同時切記勿直接在 main 分支上硬改。
