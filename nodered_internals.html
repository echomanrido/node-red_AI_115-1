核心機制 01 ・ 非阻塞 I/O

異步程式執行機制解析

解構 Node-RED 能夠在單一執行緒（Single Thread）下輕鬆吞吐數萬個 PLC 通訊封包與 MQTT 數據的底層核心——Node.js V8 引擎與 libuv 非同步事件迴圈協同架構。

  • Call Stack (呼叫棧)：同步 JavaScript 程式碼依序推入棧頂執行，執行完畢即刻彈出釋放。
  • C++ Bridge & Worker Pool：耗時的檔案 I/O、PLC 序列通訊或網路請求，立即指派至背景 libuv 4 執行緒池處理，不卡死主執行緒。
  • Microtask 插隊機制：process.nextTick() 與 Promise 在各階段切換前擁有最高優先級，能即刻插隊保證關鍵數據即時性。
  • 工控黃金準則：Function 節點內絕不可寫死循環或同步耗時等待（如同步 sleep），否則將凍結整個工廠的 SCADA 監控迴圈！

核心機制 02 ・ 視覺化流管線

視覺化工具訊息傳遞路徑

揭開 Node-RED 畫布連線 (Wire) 的底層實體！畫布上的每條線並非魔法，而是 Node.js 執行期註冊的 EventEmitter 事件管線與記憶體指針傳遞過程。

  • 事件驅動模型：上游節點觸發 node.send(msg)，透過連線配置觸發下游節點的 node.on('input') 監聽回調。
  • 記憶體引用傳遞 (By Reference)：若一條線分支分流至多個節點，傳入的是同一個記憶體位址；底層透過 RED.util.cloneMessage() 深拷貝避免分支間互相竄改。
  • Context 儲存分層架構：Node-RED 提供 Node、Flow、Global 三層記憶體狀態管理，可對接記憶體、本地檔案或 Redis 工業快取。
  • Backpressure (背壓機制)：非同步 send(msg) 與 done() 模式，避免高頻感測器塞爆緩衝佇列導致記憶體溢出 (OOM)。
