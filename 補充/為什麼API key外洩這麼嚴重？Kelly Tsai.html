Chapter 01

生活中的 API：就是「點餐窗口」

不管是公車到站、天氣預報、還是 ChatGPT，背後都在用同一個機制運作。

1. 點餐窗口 (API)

你不需要走進廚房，也不必了解廚師怎麼備料煮菜。你只需要來到約定好的窗口，對照菜單點選，窗口就會把做好的料理（資料）端出來。

2. 菜單 (API 文件)

雙方約定好的規則與格式。規定你要講什麼話（英文或代碼）、點餐格式是哪種（如 JSON）。每家餐廳（OpenAI、中央氣象署）的菜單規格都不同。

3. 會員卡 (API Key)

這張會員卡直接綁定你的信用卡。窗口「認卡不認人」，誰拿這張卡去點餐，所有消費與用量帳單都會無條件記在你頭上！

Chapter 02

API 請求 (Request) 單據上的 4 件大事

每次點餐送出的 JSON 單子，一定包含這 4 種資訊。

01. 送到哪裡？

URL / 端點 (Endpoint)

跟上網網址一樣。例如氣象局底下有颱風、地震、雨量，各自分屬不同網址，送錯網址就問錯人。

02. 做什麼動作？

HTTP Method

最常見兩種：GET 是「拿」（索取資料）；POST 是「送」（把一包資料送過去請他運算處理）。

03. 要什麼內容？

Params / Body

詳細要求。比如地點指定「台北市」、時間指定「明天」，或是請 AI 回答問題時傳送的提示詞 (Prompt)。

04. 你是誰？

API Key (授權碼)

帶有會員身分識別碼。窗口靠這把 Key 知道要找誰請款、確認每分鐘是否超標呼叫。

看懂錯誤碼，不再只會無腦複製問 AI

404 Not Found

地址寫錯了！伺服器根本找不到你指定的窗口網址。

401 / 403 Forbidden

Key 不對或權限不足！檢查金鑰是否打錯或已被後台撤銷。

429 Rate Limit

呼叫太快或額度花光了！這是最常見因為餘額不足跳出的錯誤。

500 / 503 Error

對方的伺服器掛了或過載，稍等片刻通常會自行修復。

Critical Security

千萬別讓 Key 裸奔！API Key 外洩三大地雷

資安公司統計：光是一年公開的 GitHub 就被掃出破百萬組 AI 密鑰！

致命坑 1

直接寫在前端 (HTML/JS)

前端程式是發送到別人的瀏覽器上跑的。任何人只要按 F12 打開開發者工具，你的 Key 就無所遁形，等同把信用卡卡號貼在公佈欄上！

致命坑 2

不小心 Push 到 GitHub

網路上有成千上萬的機器人爬蟲 24 小時瘋狂掃描公開 Commit。一旦上傳，幾秒內你的 Key 就會被拿去轉賣或批次消耗。

致命坑 3

填入不明第三方工具

有些來路不明的擴充套件或包裝網站要求你貼上 API Key。一旦後台未加密或惡意截取，帳單立刻爆掉。

業界工程師的 4 道安全防護盾

1

使用 .env 配合 .gitignore

將金鑰放在獨立的 .env 檔案，並務必在 .gitignore 加入該檔名，防止程式碼上傳時夾帶金鑰。

2

前後端分離 (Key 永遠放後端)

前端負責呈現介面，需要花錢的 API 呼叫全部由後端（Node.js / Python 等）發起，前端永遠接觸不到金鑰本體。

3

設定嚴格的使用上限 (Spending Limit)

到 OpenAI / Anthropic 後台設定每月的 Soft/Hard Limit（例如每月 10 美金）。就算程式出 Bug 瘋狂循環，到了上限也會自動中斷。

4

外洩時：立刻「撤銷 (Revoke)」而非只建新的

光是建立一把新 Key，舊的還是繼續有效！必須進後台將外洩的金鑰按下 Delete / Revoke。

// 最佳實踐：.env 與後端代理
# .env (絕對不要 commit)
AI_API_KEY="sk-proj-xxxxxxxxxxxxxxxx"
// server.js (後端代打)

app.post('/api/ask', async (req, res) => { const result = await fetch(API_URL, { headers: { 'Authorization': `Bearer ${process.env.AI_API_KEY}` }, body: JSON.stringify({ prompt: req.body.prompt }) }); res.json(await result.json()); });

✨ 前端只需呼叫自己的 /api/ask，完全不會暴露任何金鑰！
Chapter 04

多模型切換救星：AI Gateway (萬用轉接頭)

想同時使用 OpenAI、Claude、Gemini 與平價開源模型？不必管理三倍的麻煩。

概念：出國用的萬用轉接頭

每個國家的插座形狀都不同（各家 SDK 傳輸格式都不一樣）。Gateway 站在中間，你永遠只要用一套統一的寫法點餐，它會自動幫你轉譯成每一家看得懂的格式。

智慧路由 (Smart Routing) 省錢 20~40%

依據任務複雜度自動派工：簡單的翻譯與整理丟給每百萬 Token 只要 4 美金以內的平價模型（如 DeepSeek/GLM）；高難度邏輯再交給 Opus 或 GPT-4o。

只需管理一把 Key

更換底層模型只要改程式裡的一個字串名稱與 baseURL，不需要逐一到三五個平台各自綁卡、儲值與更換金鑰。

傳統方式 vs Gateway 模式
傳統手動串接
  • 要註冊 OpenAI、Anthropic、Google 三個帳號
  • 分開綁定 3 張信用卡、管理 3 份用量帳單
  • 程式碼需要安裝並維護 3 套各自特有的 SDK
採用 AI Gateway
  • 單一帳戶、單一金鑰存取數百種模型
  • 切換模型只要改 model: "claude-3-5-sonnet"
  • 支援自動備援（Fallback）與智慧動態分流

課後回顧：串接 API 的黃金三定律

Rule 01
Key 不進前端、不進 Git

永遠放後端環境變數，有專案做完就立即撤銷廢棄金鑰。

Rule 02
一定要設定消費上限

無論是練習還是正式專案，都設定硬性月額度（如 $5 ~ $20）。

Rule 03
記住 API 本身沒有記憶

對話越長，送出的歷史 Token 越多，費用隨之遞增，注意 Token 掌控。

軟體系統互通的核心哲學是「黑箱與介面分離」：使用者（Client）只需專注於送出合格的請求，後台（Server）專注於高效率烹煮與返回資料，兩者各司其職。

Chapter 03｜Request 4 大要素、狀態碼與「無記憶性」 04:04 - 07:00
原音重點：「每次發出的 JSON 單子有 4 個資訊：1. 送到哪裡（URL 網址）、2. 做什麼動作（GET 是拿、POST 是送）、3. 要什麼內容（Params/Body）、4. 你是誰（API Key 授權碼）……另外窗口是不認得你的（Stateless）！每一張單對它都是全新的。」

理解狀態碼是 Debug 的第一步：404 是尋址錯誤、401 是認證失敗、429 是額度或流速被拒。另外由於 RESTful 架構的「無狀態（Stateless）」特性，伺服器不保存上次的上下文，AI 記憶功能必須靠每次傳輸歷史紀錄來重現。
