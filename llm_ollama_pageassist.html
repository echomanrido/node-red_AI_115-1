Ollama + Page Assist
地端大模型部署與聯網 RAG 完全指南

全面掌握工業自動化現場最廣泛使用的輕量級推論引擎 Ollama！從 Windows 環境下載安裝、GPU 顯卡硬體加速驗證、Llama 3.2 Vision 與 Gemma 2 模型拉取、自定義 Modelfile 與上下文長度調校，到搭配 Chrome 擴充外掛 Page Assist 實現圖形化 Web UI、SearXNG / Google 即時聯網搜尋與本地文件向量檢索 (RAG)！

1

Ollama 安裝配置與系統常駐設定

1.1 下載與安裝

前往官方網站 ollama.com/download/windows 下載 OllamaSetup.exe，執行安裝後系統列右下角會出現羊駝圖示，表示背景服務已啟動並監聽 127.0.0.1:11434。

1.2 系統環境變數優化（重要！）

預設情況下，Ollama 會將巨大模型存放在 C 槽（C:\Users\<使用者>\.ollama\models），極易塞滿系統槽。可於「系統環境變數」中新增：

  • OLLAMA_MODELS：設定至大容量磁區，例如 D:\ollama_models。
  • OLLAMA_HOST：若欲允許局域網其他電腦（如同一廠區的工控機）訪問，可設為 0.0.0.0:11434。
  • OLLAMA_ORIGINS：設為 * 以允許跨來源（CORS）資源共享，供網頁前端或 Node-RED 調用。

1.3 終端命令驗證

# 檢查 Ollama 版本 ollama --version # 查看目前系統正在運行的模型與顯存佔用 ollama ps # 查看本地已下載的所有模型庫 ollama list
2

模型拉取、視覺多模態與 Modelfile 定制

2.1 推薦工業常用模型選型表

模型名稱參數量記憶體 / VRAM 需求典型應用場景
llama3.2-vision 11B 約 8 GB ~ 12 GB 工廠儀表拍照讀數、瑕疵外觀視覺辨識、圖文多模態分析
gemma2:9b 9B 約 6 GB ~ 8 GB Google 高性能輕量大模型、邏輯推理與常識問答極佳
qwen2.5-coder:7b 7B 約 5 GB ~ 7 GB 工業程式設計、C# / Python / Structured Text (ST) 程式碼生成
nomic-embed-text 137M 約 500 MB 專用文字向量嵌入 (Embedding)，供本地 RAG 文件比對檢索

2.2 命令行運行實戰

# 下載並直接進入互動對話 ollama run gemma2:9b # 下載視覺多模態模型 ollama pull llama3.2-vision # 圖片傳入測試 (在提問中加入圖片路徑) # "請分析這張儀表照片指針讀數是幾 bar: C:\data\meter.jpg"

2.3 撰寫 Modelfile 打造專屬工業 AI

建立文字檔 Modelfile，調整記憶體長度與系統人設，避免長文本截斷：

FROM gemma2:9b # 提高上下文長度至 8192 tokens (預設通常為 2048) PARAMETER num_ctx 8192 # 設定隨機度 (0.0~1.0)，工控嚴謹排查建議調低 PARAMETER temperature 0.3 # 注入系統級角色提示詞 (System Prompt) SYSTEM """ 你是一位擁有 20 年現場實務經驗的機電整合與智慧工廠顧問。 面對使用者的問題： 1. 一律使用繁體中文專業回答。 2. 針對設備故障，先列出安全防護注意事項（如斷電掛牌 LOTO），再依優先權提供排查步驟。 """
# 根據 Modelfile 建構自定義模型並啟動 ollama create my-factory-ai -f ./Modelfile ollama run my-factory-ai
3

Page Assist 瀏覽器擴充功能與 Web Search 聯網外掛

3.1 安裝與介面連線

在 Chrome 或 Edge 線上應用程式商店搜尋 Page Assist - A Web UI for Local AI Models 並點擊安裝。點開外掛後，確認連線網址為 http://localhost:11434，下方會自動同步列出本機剛才 pull 下來的所有 Ollama 模型。

3.2 啟用 Web Search (即時聯網能力)

本地 LLM 的訓練知識庫截止日固定，若欲查詢最新零件料號或突發新聞，可在 Page Assist 設定頁中啟用 Web Search：

  • 搜尋引擎選擇：支援 SearXNG（推薦開源免 API Key 伺服器，如 https://searx.space/）、Google Custom Search API 或 DuckDuckGo。
  • 執行原理：當使用者輸入問題時，外掛先在背景呼叫搜尋引擎抓取前 3~5 篇網路摘要，再以 Prompt 注入地端模型（Prompt Injection），由地端模型進行繁體中文統整並附上網路來源連結。
RAG vs Web Search 差異：
Web Search 適合「即時動態資訊」；而企業內部的機台維護手冊、配線圖與產線機密，絕不能上網搜尋，這時就需要依靠本地 Embedding 向量模型與本地文件知識庫（RAG）！
4

Ollama 原生 REST API 與 Node-RED 串接呼叫

Ollama 在背景內建高效能 HTTP API 伺服器，不需透過任何額外 SDK，即可用純 HTTP POST 達成遠端自動化調用：

# 終端機 cURL 測試呼叫 API curl http://localhost:11434/api/generate -d '{ "model": "gemma2:9b", "prompt": "請用繁體中文說明三相感應馬達過載跳脫的排查步驟？", "stream": false }'

Node-RED 實作流範例：

當產線感測器偵測到異常震動時，Node-RED 觸發 Function 節點組織資料並發送請求：

// Node-RED Function 節點代碼 msg.headers = { 'Content-Type': 'application/json' }; msg.payload = { model: "gemma2:9b", prompt: `[現場設備警報]\n馬達編號: Pump-A\n異常狀態: 振動頻率超標 25%，電流升至 14A\n請給出可能的機械軸承或電氣故障判定與建議。`, stream: false }; return msg; // 後接 [http request] 節點： // Method: POST // URL: http://localhost:11434/api/generate
