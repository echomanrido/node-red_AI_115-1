揭秘 Ollama：從 Go 協調器 到 llama.cpp 矩陣推論

一句話看懂 Ollama 是什麼？

Ollama 是一個專為「本地端運行大語言模型」設計的高效能封裝框架。 它就像是 AI 界的 Docker——將複雜的權重下載、GGUF 格式解析、GPU/CPU 動態顯存切層，以及 OpenAI 兼容的 REST API 全部打包成一個極簡的守護程序，讓一般開發者無需配置繁瑣的 Python/CUDA 環境，只需一條指令即可在本機暢享頂級開源模型。

● 零環境依賴：單一二進位執行檔
● 極致效能：C++ 底層原生矩陣加速
● 生態兼容：標準 HTTP/OpenAI 協議

Slot-based 併發排程

llama.cpp 實作了插槽模型（Slots）。Ollama 透過 OLLAMA_NUM_PARALLEL 參數決定開闢多少槽位。

// 多請求併發共用模型
Slot 0: User A [KV Cache 1]
Slot 1: User B [KV Cache 2]
權重 Weight 僅保留一份 (唯讀共享)
✨ 好處：不需重複載入多份數 GB 權重，大幅提升伺服器 QPS。

KV Cache 前綴快取復用

在連續對話或包含固定 System Prompt 的場景下，前面對話的 Key/Value 矩陣不需要從第 1 個 Token 重複矩陣相乘。

對話輪次 1: [系統提示 + 問題一]
對話輪次 2: [重算前文] ➔ 重用快取
首字響應延遲 (TTFT) 降低 80%+
✨ 好處：長文本上下文對話時，首個字回傳近乎零延遲。

進程隔離與 Keep-Alive

Go 守護伺服器與 C++ 推論 Runner 獨立為不同進程。即使 CUDA 爆顯存 (OOM) 或產生崩潰，僅會終止該子進程。

OLLAMA_KEEP_ALIVE=5m (預設)
推論結束 ➔ 保持進程與 VRAM 狀態
超時 5 分鐘無請求 ➔ 優雅釋放顯存
✨ 好處：守護進程永不中斷，兼顧連續請求效能與記憶體節省。
底層技術細節

為什麼 Ollama 載入大模型幾乎是「秒開」？

傳統 Python/PyTorch 載入 70 億參數模型需要幾十秒甚至數分鐘，而 Ollama 在啟動時數百毫秒內就完成準備。這歸功於 GGUF 規範與作業系統的 mmap 機制。

GGUF 格式與 mmap 零拷貝 (Zero-Copy) 記憶體映射 Instant Load via OS Page Cache

GGUF 二進位檔案格式 (由 llama.cpp 制定)

  • Header 結構化自包含：包含模型架構、Tokenizer 分詞表、注意力頭數量、量化型別（如 Q4_K_M）。
  • 嚴格對齊 (Data Alignment)：張量權重的起始偏移量按照 32-byte 邊界對齊，完美配合 CPU SIMD/GPU DMA 直接讀取，無需反序列化。

mmap 記憶體映射黑魔法

  • 非阻塞式載入：透過系統呼叫建立虛擬記憶體指標，並不立即把整個檔案讀進實體 RAM。
  • 按需分頁換入 (Page Fault)：只有當 Transformer 計算到該層權重時，作業系統才將對應區塊快取入記憶體；同時利於多進程間共享 Page Cache。
