Technical Insight

1. 支援度差異的四個根本原因

不是開發團隊偏心，而是歷史累積的運算生態庫、軟體發行與硬體架構包袱所致。

生態成熟度：CUDA 領先近二十年

NVIDIA 從 2006 年便深耕 CUDA，其軟體 API、底層編譯器（NVCC）與上層深度學習函式庫（cuBLAS、cuDNN）極度成熟。社群開源核心 llama.cpp 的 CUDA 後端開發早、測試最全面，Bug 也最少。

AMD LLVM GFX 標靶碎片化

AMD ROCm 的 rocBLAS 等矩陣核心需針對特定的微架構（如 gfx1030, gfx1100）單獨編譯。若某張顯卡的微架構不在預先打包的核心中，就會在啟動時直接 Crash 或退回 CPU。

安裝檔體積爆炸問題

NVIDIA 具備良好的二進位前向相容性（PTX / SASS）。相反地，若 Ollama 要在安裝包中預載市面上所有 AMD RX 顯卡、APU 的 ROCm 核心函式庫，安裝檔體積將達到數個 GB 以上，因此官方僅打包主流 RDNA2/RDNA3 架構。

AMD 初期重心偏向伺服器與 Linux

AMD ROCm 長期專注於 Linux 伺服器級 GPU（如 Instinct MI 系列），消費級顯卡（Radeon RX）以及 Windows 平台的支援在近年才加速推進，各版本驅動與 API 變動頻繁，適配難度顯著提高。

Hardware Specs

官方硬體支援規格指南

根據 Ollama 官方文檔標準整理，涵蓋各大主流平台與架構需求。

訪問官方原檔 docs.ollama.com/gpu
NVIDIA GPU CUDA
  • 運算架構限制： Compute Capability 5.0 或更高版本。
  • 支援世代： Maxwell、Pascal、Turing、Ampere、Ada Lovelace、Blackwell 全系列。
  • 驅動要求： 需安裝標準 NVIDIA 官方專用驅動程式（支援 WSL2 與原生 Windows/Linux）。
AMD Radeon GPU ROCm
  • 原生開箱支援： RDNA3 架構（RX 7600/7700/7800/7900 等）與部分 RDNA2 高階卡。
  • Linux vs Windows： Linux 支援較廣泛；Windows 現行版本重點支援官方指定 Radeon 產品。
  • 非原生卡解決方案： 透過 GFX 代碼覆寫或採用 Vulkan 後端加速。
Apple Silicon Metal API
  • 架構核心： 透過 Apple Metal API 提供原生效能加速。
  • 巨大優勢： 統一記憶體架構（Unified Memory），Mac mini / Studio / MacBook 可直接運行極大模型。
  • 晶片覆蓋： M1、M2、M3、M4 全系列晶片原生開箱即用。

Practical Guide

AMD 顯卡必備救援與覆寫步驟

當您的 AMD 顯卡顯示支援但 Ollama 仍以 CPU 執行時的具體解決方案。

方案 A：Linux 下使用 HSA_OVERRIDE_GFX_VERSION Systemd / CLI

以 RX 6700 XT 或 RX 6600 等未完全開箱預設相容的顯卡為例，可強制告知 ROCm 執行時將其視為已支援的 10.3.0 架構核心：

# 單次終端機測試啟動
export HSA_OVERRIDE_GFX_VERSION=10.3.0
ollama serve
# 若為 Systemd 服務，請編輯 /etc/systemd/system/ollama.service
Environment="HSA_OVERRIDE_GFX_VERSION=10.3.0"
方案 B：Windows 環境變數設定 Windows 10 / 11
  1. 在 Windows 搜尋列輸入 環境變數，開啟「編輯系統環境變數」。
  2. 點選「環境變數」按鈕，在「使用者變數」或「系統變數」點選「新增」。
  3. 變數名稱填入：HSA_OVERRIDE_GFX_VERSION
  4. 變數值填入：11.0.0（RX 7000 系列相容）或 10.3.0（RX 6000 系列相容）。
  5. 完整退出系統匣中的 Ollama 並重新啟動軟體。
方案 C：通用 Vulkan 加速備援方案

若您的顯卡過舊（例如 RX 580、Vega 56/64）或為 AMD APU 內顯，ROCm 已不再提供官方指令集支援。此時可透過 Vulkan 支援版本進行硬體加速，享受跨廠牌 GPU 推論功能。
