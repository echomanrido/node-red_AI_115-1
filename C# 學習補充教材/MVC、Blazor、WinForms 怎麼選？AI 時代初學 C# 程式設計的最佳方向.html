2. 三大技術深度解析與優缺點對比

00:01:12 Windows 桌面應用

Windows Forms (WinForms)

所見即所得的經典桌面表單開發

屬於傳統 Windows 桌面應用程式。最大特色是在 Visual Studio 設計工具中，可以直接用滑鼠拖拉文字輸入框（TextBox）、標籤（Label）、按鈕（Button）與資料表格（DataGridView）。

✅ 技術優勢

  • • 控制項具體直覺，事件觸發（如按鈕 Click）極易理解。
  • • 不需先學網頁排版語法，適合零程式經驗快速建立成就感。

⚠️ 先天限制與適用場景

  • • 無法跨平台：不能直接用手機、平板或瀏覽器操作。
  • • 部署維護：每台電腦需安裝執行檔，後續版本更新需額外規劃。
  • • 最佳場景：純公司內部 Windows 電腦專用的管理系統。

Blazor

使用 C# 打造現代互動式網頁應用

使用 HTML 與 CSS 設計畫面，但前端互動邏輯可以直接用 C# 撰寫！例如輸入供應商名稱即時搜尋、更新清單與選取項目，原本需寫 JavaScript 的工作全都能用 C# 事件完成。

✅ 技術優勢

  • • 前後端統一使用 C# 語言與物件模型，不用在 JS 與 C# 間頻繁切換。
  • • 支援跨裝置瀏覽器操作，非常值得想寫 C# 網頁管理系統者優先學習。

⚠️ 學習門檻與部署考量

  • • 仍需具備基礎 HTML/CSS，並理解元件生命週期、資料繫結與狀態管理。
  • • 若採 Interactive Server 模式，互動需維持與伺服器的即時連線，部署時須考量網路品質與伺服器資源。

1. 開場與問題背景：AI 協作時代，初學 C# 的三大技術抉擇

哈囉大家好，我是卓老師的語音助理「巨蟹座阿關」。在上一集影片中，我們透過「西藥批發管理系統」的實戰展示，帶大家看見了 AI 協作開發商用軟體的強大潛力。緊接著許多準備踏入 C# 程式設計領域的初學者便提出了一個非常實際的問題：「我想用 C# 開發一套真正可以拿來商用的管理系統，但在有 AI 輔助寫程式的今天，我到底該從 ASP.NET MVC、Blazor 還是 Windows Forms (WinForms) 哪一種技術開始？」

很多人以為有了 AI 幫忙產出程式碼之後，選哪一種架構好像都差不多；但事實上，這三種技術在運作原理、操作介面體驗以及實際部署維護上完全不同。選對符合自己目標的起點，才能讓學習過程少走許多冤枉路。

核心提問（技術核心）： AI 解決的是「語法撰寫速度」，但開發者仍必須決定系統要跑在「Windows 單機桌面」還是「跨裝置瀏覽器」，這正是本集要幫初學者釐清的關鍵分水嶺。
00:01:12 Windows Forms (WinForms) Windows 桌面應用程式

2. 第一種技術：Windows Forms (WinForms) —— 視覺拖拉最直覺的入門磚

首先來看第一種技術：Windows Forms，簡稱 WinForms。它是微軟非常經典的 Windows 桌面應用程式開發框架。對於完全沒有程式經驗的初學者來說，WinForms 最大的魅力在於 Visual Studio 內建的視覺化設計工具——你可以直接用滑鼠從工具箱把文字輸入框（TextBox）、標籤（Label）、按鈕（Button）以及資料表格（DataGridView）拖拉到視窗畫面上擺放。

這種「所見即所得」的開發方式，讓控制項非常具體，點兩下按鈕就能直接寫入對應的事件處理邏輯，初學者很快就能理解畫面與程式之間的互動關係。不過，WinForms 也有明顯的限制：它只能在 Windows 桌面環境執行，無法讓使用者直接透過手機、平板或其他作業系統的瀏覽器開啟操作；此外，當公司內部有多台電腦需要使用時，軟體的安裝部署與後續版本更新也都需要額外規劃。因此，它最適合純公司內部、固定在 Windows 電腦上作業的管理系統。

✅ 適用場景與優勢

零程式基礎建立成就感、純公司內部 Windows 電腦專用系統（如櫃檯收銀、倉庫單機作業）。

⚠️ 限制與部署成本

不支援手機與跨平台瀏覽器操作，客戶端需安裝執行檔，後續版本派送與更新需額外維護。

00:02:29 Blazor 講師推薦 C# 網頁首選

3. 第二種技術：Blazor —— 用 C# 駕馭前端互動的現代網頁框架

第二種技術是近年備受矚目的 Blazor。它允許開發者使用 HTML 與 CSS 建構網頁外觀，但最吸引人的突破在於：原本在網頁前端必須依靠 JavaScript 處理的互動邏輯，在 Blazor 中可以直接使用 C# 來撰寫！舉例來說，在「西藥批發管理系統」的採購畫面裡，當操作人員輸入供應商名稱的關鍵字時，畫面要即時篩選出符合的廠商清單並讓使用者點選，這類動態互動都能直接透過 C# 事件處理輕鬆完成。

當然，使用 Blazor 依然需要具備 HTML 與 CSS 的基礎排版觀念，並且要學習元件生命週期、資料繫結（Data Binding）與狀態管理。此外，如果你採用的是 Blazor Interactive Server 運作模式，因為每一次前端互動都需要透過 SignalR 與伺服器維持即時連線，未來系統正式上線部署時，就必須把網路連線品質與伺服器記憶體資源納入評估。整體而言，如果你的目標是開發一套跨裝置、用 C# 貫穿前後端的網頁管理系統，Blazor 非常值得優先學習。

💡 技術核心：前後端統一 C#

透過 Razor 元件與 @bind 資料繫結，直接用 C# 事件處理即時搜尋與局部畫面更新，無需手寫繁瑣 JavaScript。

⚠️ Interactive Server 部署考量

互動過程需維持與伺服器的即時連線（Circuit），多人同時上線時須留意網路穩定度與伺服器資源配置。

00:03:59 ASP.NET MVC 本專案示範首發架構

4. 第三種技術：ASP.NET MVC —— 職責分離、資源最豐富的經典網站架構

第三種則是歷久彌新、架構非常成熟的 ASP.NET MVC。它的核心精神在於將應用程式的職責明確劃分為三大區塊：負責資料結構與商業模型的 Model、專責畫面呈現的 View，以及負責接收瀏覽器請求並協調流程的 Controller。這種高度解耦的分層設計，非常有利於大型商用系統的程式碼整理、團隊分工與長期維護。

由於 MVC 發展歷史悠久，網路上的教學文章、開源套件與企業實戰範例極為豐富，非常適合處理標準表單輸入與資料查詢功能。不過對初學者而言，選擇 MVC 意味著除了後端的 C# 之外，通常還必須同時學習前端的 HTML、CSS 以及 JavaScript（或 jQuery）；一旦畫面需要做到不重新整理網頁的即時動態互動，就得透過前端腳本發送非同步請求來配合，初期需要同時吸收的網頁技術觀念較多。

✅ 架構優勢

Model / View / Controller 職責清晰分離，企業維護性極高，教學資源與 AI 訓練語料最豐富。

⚠️ 學習曲線挑戰

除 C# 外需同步掌握 HTML、CSS 與 JavaScript / jQuery 才能打造流暢的前端即時互動體驗。

00:05:24 實戰案例對比 採購登錄流程

5. 實戰功能大比拚：以「採購登錄」為例，業務規則才是真正靈魂

為了讓大家更有具體畫面，我們直接以西藥批發管理系統中最核心的「採購登錄」功能來做比較。無論你選用哪一種技術，背後的共通商業流程都是完全一致的：第一步先選擇供應商；第二步搜尋並選取西藥商品；第三步輸入採購數量與單價（系統自動依公式 $\text{Subtotal}_i = Q_i \times P_i$ 算出單筆小計，並加總 $\text{Total} = \sum_{i=1}^{n} \text{Subtotal}_i$ 計算整張採購單總金額）；第四步則是儲存採購草稿寫入資料庫。

三種技術的差異僅在於「介面層如何實作這些互動」：WinForms 是透過桌面文字框、DataGridView 表格與視窗事件處理完成；Blazor 是透過 Razor 元件與 C# 事件完成即時搜尋與明細更新；MVC 則是透過 Razor View、Controller 搭配必要的前端 JavaScript 互動程式來處理。因此，初學者真正應該學習的重點，是先把商業需求與業務規則定義清楚——只要底層規則規劃合理，未來無論要套用到哪一種前端技術都能水到渠成！

心法
業務規則優先原則： 先定義清楚「供應商驗證 → 商品計價（$\text{Subtotal}_i = Q_i \times P_i$）→ 總額加總（$\text{Total} = \sum \text{Subtotal}_i$）→ 草稿狀態控管」，介面只是這套商業邏輯的不同外衣。

6. AI 時代的初學者選型指南與五大不可取代核心能力

綜合以上分析，在 AI 時代初學者該如何做出最適合自己的選擇？我們提供三個明確的切入建議：第一，如果你完全沒有程式經驗，想先直覺認識按鈕、文字框與事件處理，可以從 WinForms 入手建立信心；第二，如果你的目標是開發瀏覽器跨裝置商用系統，建議優先考慮 Blazor，前後端都能維持一致的 C# 語言與工具鏈；第三，如果你想學習企業最成熟的經典網站架構，且願意一併接觸前端技術，ASP.NET MVC 依然極具學習價值（這也是我們示範專案將 MVC 擺在第一個前端實作順位的原因）。

更重要的是，大家必須認清一個事實：AI 只能協助提高寫程式的效率，並不能取代工程師的專業判斷！開發者本身仍須具備基本的程式架構與語法閱讀能力，並親自精進與負責五大關鍵領域：資料庫設計、業務規則定義、權限控管、系統安全性，以及完整的實際測試。
