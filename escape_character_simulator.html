💡 跳脫字元 (Escape Character) 核心定義：

在電腦科學與遠端通訊中，當跳脫字元（Escape Character）放在字元序列時，它將對它後續的幾個字元進行替代並解釋。跳脫字元是元字元的一種特殊情況。通常，判定某字元是否為跳脫字元由上下文確定。

❌ 致命錯誤：單反斜線 \ 容易觸發 ENOENT

在 JS 程式碼中直接用單反斜線宣告字串，會導致 \T、\n、\t 被誤判為特殊字元：

// 程式碼撰寫
msg.filename = "...";
實際記憶體解析結果：
原因：\t 被解析為 Tab 水平定位點，造成路徑破碎！
解法一：雙反斜線 \\ JS Function 節點

在 JavaScript 中，第一個 \ 代表跳脫標記，第二個 \ 才是真正的反斜線字元：

// 程式碼撰寫
msg.filename = "...";
實際記憶體解析結果：
適用：純 Windows 本地環境、嚴格遵循反斜線語法之場合。
⭐ 最佳實踐：正斜線 / 跨平台通用推薦

Node.js（包括 Node-RED）底層的 fs 與 path 模組在 Windows 環境下完全相容正斜線 /：

// 程式碼撰寫 (極度簡潔)
msg.filename = "...";

優勢：完全杜絕跳脫字元轉義問題，同時相容 Windows、Linux 與 macOS！

常見跳脫字元 (Escape Characters) 規格速查

整理維基百科與各程式語言（C、JavaScript、Python、JSON）通用的轉義符號。

跳脫符號 (Escape Code) 字元名稱 (Name) ASCII / Unicode 十六進制 功能說明與實務應用
\\ 反斜線 (Backslash) 0x5C (\u005C) 輸出單一反斜線符號本身，常用於 Windows 檔案路徑與正規表達式。
\n 換行符 (Newline / Line Feed) 0x0A (\u000A) 在字串中換至下一行（Unix/Linux 換行格式）。在 Node-RED 寫入 CSV 或文字檔時必備。
\r 回車符 (Carriage Return) 0x0D (\u000D) 將游標移回行首。Windows 系統標準換行為 \r\n (CRLF)。
\t 水平定位點 (Horizontal Tab) 0x09 (\u0009) 插入一個 Tab 跳格空白（通常為 4 或 8 個字元寬），常用於對齊報表數據。
\' 單引號 (Single Quote) 0x27 (\u0027) 在單引號包裹的字串中插入單引號（如 'It\'s OK'），避免字串提早閉合。
\" 雙引號 (Double Quote) 0x22 (\u0022) 在雙引號包裹的字串或標準 JSON 格式中插入雙引號（如 "He said: \"Hi\""）。
\b 退格 (Backspace) 0x08 (\u0008) 使游標回退一格，刪除前一個字元。
\uXXXX Unicode 萬國碼 4 位十六進制 以 Unicode 編碼表示特定字元，如 \u4e94\u80a1 代表「五股」。

Node-RED 實戰中的跳脫字元最佳實踐

掌握 Function 節點組裝路徑、UI 節點顯示與 JSON 格式轉換的避坑秘笈。

1. Function 節點動態讀圖路徑組裝 JavaScript

在 Function 節點內組裝圖片路徑時，強烈推薦使用正斜線 /，代碼最乾淨且完全不會產生跳脫錯誤： 

//  推薦寫法：使用正斜線 / (簡潔且跨平台)
const basePath = "D:/Test_Wugo/拉拉隊/";
const memberName = msg.payload; // 如 "霍諾德"
msg.filename = basePath + memberName + ".png";

return msg;
2. 寫入 CSV 檔案與 \r\n 換行 Write File

當利用 write file 節點將 SCADA 數據串接為 CSV 報表時，利用 \n 或 \r\n 實現換行： 

// 產線每筆數據加上換行符 \r\n 寫入 CSV
const timestamp = new Date().toISOString();
const logLine = `${timestamp},${msg.topic},${msg.payload}\r\n`;

msg.payload = logLine;
return msg;
