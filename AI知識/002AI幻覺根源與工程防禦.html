為什麼大型語言模型會一本正經胡說八道？

AI 幻覺不是系統 Bug，而是自回歸機率取樣模型在數學統計上的必然結果。在機電工控與 Node-RED 自動化系統中，我們不能祈禱 AI 不出錯，必須透過確定性的規格約束 (Spec) 與安全看門狗護欄守住底線。

防禦核心原則
確定性代碼門禁

幻覺的三大底層數學根源

1 自回歸機率取樣 (Softmax Sampling)

LLM 每預測一個詞都在計算整個詞表 (Vocab) 的機率分布。即使錯誤詞彙機率只有 5%，在數百個 Token 的長文中，隨機取樣必然會累積偏差，導致幻覺滾雪球。

2 討好傾向與知識截止 (Sycophancy)

經人類反饋強化 (RLHF) 後的模型傾向於「順應提問者的語氣與預設假設」，即使提問者的前提是錯的，AI 也會配合編造看起來合理的解釋。

3 注意力稀釋與上下文盲區

當提示詞過長或缺乏明確標記時，Self-Attention 權重被稀釋，模型容易丟失關鍵工控參數 (如暫存器範圍 D0~D1000)。

工業工程多層防禦護欄 (Guardrails)

1. Grounding (真實資料錨定)

絕不讓 AI 憑空捏造。把真實硬體清單、Modbus Address Mapping 透過 RAG 或系統提示詞完整注入。

2. JSON Schema 結構化輸出強制約束

利用 OpenAI Structured Outputs 或 Function Calling，在解碼階段直接封殺非法 Token，格式 100% 符規。

3. 確定性單元測試與 Linter 驗收

AI 產出的代碼絕不直接下發 PLC！必須在沙箱環境執行自動化測試與靜態語法檢查。

4. Human-in-the-Loop 實體硬體門禁

高風險硬體致動器 (馬達、閥門) 必須加入人工確認或實體急停看門狗 (Watchdog) 雙重保護。
