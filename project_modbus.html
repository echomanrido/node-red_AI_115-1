工業通訊標準：Modbus 通訊協定全解構
Modbus TCP (MBAP) 與 Modbus RTU (CRC-16) 實戰剖析

Modbus 為工業自動化與 SCADA 監控系統中廣泛採用的通用應用層通信標準。本專題深入探討 Modbus 四大核心資料模型（Coils、Discrete Inputs、Input Registers、Holding Registers），從乙太網端 Modbus TCP（Port 502、MBAP Header 報頭封裝）到現場匯流排 Modbus RTU（RS-485 差動傳輸、3.5 字元幀超時、CRC-16 偵誤碼校驗），並對接三菱 FX5U / FX3U PLC 軟元件位址，建構完整的軟硬體工業通訊實戰體系！

PDU 獨立性：不論是 RTU 還是 TCP，中間的 [Function Code] + [Data] 結構完全相同，差別僅在最外層的傳輸封裝！

Modbus TCP 實戰指南：MBAP Header 報頭與封包實例

Modbus TCP 運行於 TCP/IP 協定之上，標準通訊連接埠為 Port 502。為了適應網路傳輸，協定在 PDU 前面加入了 7 個位元組的專屬標頭 MBAP (Modbus Application Protocol Header)：

MBAP Header (7 Bytes) 欄位定義表

欄位名稱長度說明與用途範例數值
Transaction ID (傳輸識別碼) 2 Bytes 用於請求與回應的配對識別。客戶端發送的值，伺服器必須原樣返回。 19 B2
Protocol ID (協定識別碼) 2 Bytes 固定為 00 00，代表標準 Modbus TCP 協定。 00 00
Length (長度) 2 Bytes 指後續所有欄位（包括 Unit ID 與 PDU）的位元組總數。 00 06 (後續 6 Bytes)
Unit ID (單元識別碼) 1 Byte 從站模組 ID。在直連 PLC 時多為 00 或 IP 末段（如 FX5U IP .10 設為 0A），在連接 Gateway 時用於指定轉發的串列從站位址。 0A (十進位 10)

實例 1：使用 01H 讀取 Y0~Y3 狀態

客戶端發送指令：

19 B2 00 00 00 06 0A 01 00 00 00 04
  • 19 B2：Transaction ID (報頭)
  • 00 00：Protocol ID (Modbus)
  • 00 06：長度 6 Bytes
  • 0A：Unit ID (模組位址)
  • 01：功能碼 01H (Read Coils)
  • 00 00：起始位址 (Y0)
  • 00 04：讀取線圈長度 (讀 4 個點 Y0~Y3)

實例 2：使用 0FH 批次置位 Y 點 (多線圈)

客戶端發送指令：

19 B2 00 00 00 09 0A 0F 00 00 00 0F 02 09 01
  • 00 09：後續位元組長度為 9 Bytes
  • 0F：功能碼 0FH (Write Multiple Coils)
  • 00 00：起始線圈位址 (Y0)
  • 00 0F：寫入線圈數量 (15 個點)
  • 02：寫入資料位元組數 (2 Bytes)
  • 09 01：資料內容 (09 代表 Y0~Y7，01 代表 Y10~Y17)

Modbus RTU 實戰指南：RS-485 現場匯流排與 CRC-16 檢校

CRC-16 循環冗餘校驗碼演算法流程

  1. 將 16 位元暫存器 CRC 初始化為 0xFFFF。
  2. 取封包第一個位元組（8-bit）與 CRC 的低位元組進行 XOR 互斥或運算。
  3. 將 CRC 向右移位 1 bit，高位補 0。
  4. 若移出的最低位（LSB）為 1，則 CRC 與多項式常數 0xA001 進行 XOR 運算；若為 0 則重複步驟 3。
  5. 重複步驟 3 與 4 直到該 Byte 的 8 個 bit 皆處理完畢。
  6. 重複步驟 2 至 5 處理下一個 Byte，直到所有資料位元組計算完畢。
  7. 最終將 CRC 拆為低位元組在前、高位元組在後附加至封包末尾。

3.5 字元時間間隔 (3.5T Character Timeout)

在 Modbus RTU 協定中，由於沒有像 ASCII 那樣的固定開頭 (STX) 或結尾 (ETX)，因此它是利用「實體線路寂靜時間（Silent Interval）」來判斷一幀封包的起止：

  • 幀開始與結束標誌：匯流排必須維持至少 3.5 個字元發送時間 的空閒。
  • 字元間隔限制：兩個相鄰位元組之間的間隔時間不得大於 1.5 個字元時間，否則接收設備將視為通訊逾時並丟棄該幀。
  • 波特率計算：在 9600 bps 下，1 個字元（10 bits）約需 1.04 ms，因此 3.5T 約為 3.65 ms。
