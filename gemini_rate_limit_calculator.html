Node-RED 中的 Rate Limiting 與 429 自動重試實作

Exponential Backoff

當 Node-RED 發送 HTTP 請求給 Gemini API 時，若遇到 429 (Resource Exhausted)，標準做法是利用 Delay 流量調步節點 或在 Function 中加入指數退避重試 (Exponential Backoff)：

// Node-RED Function: 處理 Gemini 429 錯誤與自動退避重試 if (msg.statusCode === 429) { msg.retryCount = (msg.retryCount || 0) + 1; if (msg.retryCount <= 3) { // 指數退避延遲：第 1 次等 2 秒，第 2 次等 4 秒，第 3 次等 8 秒 const delayMs = Math.pow(2, msg.retryCount) * 1000; node.warn(`[Gemini 429 超額] 將於 ${delayMs/1000} 秒後進行第 ${msg.retryCount} 次重試...`); // 傳送至 Delay 節點或直接以 setTimeout 發送 setTimeout(() => { node.send(msg); }, delayMs); return null; } else { node.error("[Gemini API] 已達最大重試次數，轉移至本地備援模型 Ollama 或發送警報", msg); return msg; } } return msg;
1. 加入 Delay 節點

在 HTTP Request 前加入 Delay 節點設為「每分鐘限制 10 則」，避免瞬間併發打滿 RPM。
